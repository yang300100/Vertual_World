# 伊瑟拉 · 旅人之书 —— 前端重构设计规格

> 本文档是**前端重构的交付规格**，供实现方（另一个编程 agent）照着落地。
> 目标场景：玩家（主视角）在一个自主推进的世界里沉浸式"经历故事"，而不是面对堆积的工程面板。
>
> 关联前端文件：`world_engine/web/index.html`、`world_engine/web/app.js`、`world_engine/web/styles.css`。
> 世界地图资源：`docs/worldbuilding/maps/planet-master.png`（经 `/world-assets/` 静态挂载）。

---

## 0. 设计总原则

- **舞台是主角**：场景是本页默认落地页，是玩家"此刻沉浸"的地方。
- **工具留在桌面**：技能 / 背包 / 装备 / 行动输入是**浮在场景上的工具**，随手拿起、用完即放，**不切页、不打断沉浸**。
- **房间靠切换**：地图 / 编年 / 关系网 / 笔记本 是"走进另一个房间"，整页切换。
- **玩家视角优先**：所有展示以**主视角人物（玩家）**为中心（"我在这、我看见谁、我能做什么"）。
- **大人和小孩分开**：世界管理（流速 / 裁判 / 人物管理）收在"编年者"区，与玩家体验隔离。

## 2. 各界面 / 面板详细设计

### 2.1 🎭 场景（默认首页 · 故事舞台）

**定位**：玩家"此刻沉浸"的舞台，是页面落地默认看到的。

组成区块（自上而下）：

1. **所在之地 + 时钟栏**
   - 当前地点名（如"黑石镇"）、世界时钟（日期 + 时间）、时间比例徽标。
   - 右侧：当前精确坐标（见 §4 坐标系统）的可读文本，例如 `E 34.2° · N 58.7°`。
2. **叙述块**：主视角当下场景的叙述文字（现有 `#scene-narration`）。
3. **故事卡片流（近期编年）**：以"卡片"呈现最近发生、且**主视角能感知**的事件（玩家同地点或 POV 相关）。每条卡片含：简短标题 / 涉及人物 / 时间。点击卡片 → 展开原文 / 跳转对应编年条目。
4. **在场的人**：与玩家当前同地点的人物列表（现有 `#nearby-characters`）。每条：头像缩写、姓名、身份；悬停/点击 → 打开人物档案（§2.6），可从中发起交谈/攻击。
5. **行动输入栏**（固定底部，见 §2.3）。

**与现前端差异**：原 `#scene` 集成了 HUD、行旅地点地图、战斗面板、位置地图等多个区块。本次把 HUD 精简上移，行旅/战斗/位置图**拆到独立空间**，场景只保留"沉浸叙述 + 在场的人 + 故事卡片"，让它真正聚焦。

---

### 2.2 浮动桌面（不切页的工具）

场景/任意房间上方，**一套常驻浮动工具面板**，用完即收，不打断当前页面：

| 工具 | 内容 | 交互 |
|---|---|---|
| ⚔ 技能 | 玩家已习得技能（技能名 + 等级/描述） | 点击技能可**带入行动框**；战斗时突出显示 |
| 🎒 背包 | 玩家背包物品（数量、类型、可交互项） | 点物品→使用/装备/掉落 |
| 🛡 装备 | 当前穿戴的武器/防具 | 显示效果加成（攻击/防御/治疗） |
| ▶ 行动 | 行动输入（自然语言） | 见 §2.3 |

- 表现形式：右/左下角**可折叠的浮动面板**，或底部工具条。点击展开为抽屉，移开焦点自动收起。
- **战斗情境下**，浮动桌面常驻并加"敌我对阵"信息（见 §2.4）。

---

### 2.3 行动输入栏（"你此刻想做什么"）

固定于场景底部、常驻。这是玩家最频繁的交互入口。

- **输入**：textarea，自然语言描述行动/对话/态度。快捷键 `Ctrl + Enter` 提交。
- **建议动作**：根据当前可交互对象（在场的人物、技能、背包物品、可行地点）动态生成快捷建议 chips，点击即填入输入框（或直接快捷执行）。
- **提交**：POST `/api/worlds/{world_id}/player/act`（接入现有 `submit_player_intent`），返回后即时刷新场景 + 反映到编年。
- **便捷操作**：从"在场的人"选某人可一键生成"与○○交谈 / 向○○攻击"的预填。

---

### 2.4 ⚔ 战斗面板

当玩家在战斗或相关情境时**自动浮现**（替代原 `#combat-panel`，但改为**更直观**）：

- **敌我对阵**：分两侧 `我方 / 敌方`，各列人物头像、姓名、血条。**同一侧 = 队友，另一侧 = 敌人**（按人物关系判定：`affinity/trust`，或是否与玩家为友/敌）。
- **我方资源**：玩家血/精/饱、当前技能、背包、装备（取浮动桌面数据）。
- **技能/道具**：点击技能或道具 → 直接作为参战动作。
- **操作**：选中敌方某人物 → 生成攻击目标；我方技能/道具 → 填充行动。

---

### 2.5 🗺 地图（实时点位图 · 切页）

**核心要求（本次重头戏）**：不显示"大概处地"，而是**玩家精确坐标点位**。

- 渲染：世界地图 `planet-master.png`（可能裁剪成"主大陆视角"更好，见 §4.6）。
- 点位：叠加在图片上（绝对定位层）。
  - **「我」（玩家）**：高亮标记（如星形 / 特定色），配当前坐标文本。
  - **附近的人**：圆点，**颜色区分关系**——友=绿 / 敌=红 / 中立=灰，图例说明含义。
  - 其他已知人物（可选）：以更淡的点显示。
- **点击点位** → 弹出该人物档案卡（姓名/身份/关系），可一键"交谈 / 攻击 / 查看详情"。
- **坐标显示**：页面固定显示玩家当前坐标（`E …° · N …°` 或归一化网格）。
- 数据来源：`WorldSnapshot.characters[]` 的 `pos_x/pos_y`（见 §4）。

---

### 2.6 🗣 人物档案（弹层，从任意处打开）

点任意人物（在场的人 / 地图点位 / 关系网节点 / 编年条目内）→ 弹出档案层：

- 基本信息：姓名、身份、所在之地、当前状态（血/精/饱）。
- **关系**：与玩家之间的 `affinity` / `trust` 值、关系标签（友/敌/中立/亲属…）。
- **回忆**：该人物的近期记忆（现有 `/characters/{id}/memories` 接口）。
- 最近与玩家相关的事件。
- 操作按钮：交谈 / 攻击 / 加入计划。

---

### 2.7 📜 编年（故事时间线 · 切页）

- 完整、可筛选的事件历史流（筛选：全部 / 战斗 / 交谈 / 行旅 / 其他）。
- 倒序时间排列（现有 `#event-list`）。可点开原文/详情。
- 来源：`GET /api/worlds/{world_id}/events`。
- 从场景"故事卡片"点击"看全部" → 跳到本页并聚焦对应条目。

---

### 2.8 🕸 关系网（动画节点图 · 切页）

- **以玩家为中心**：中心节点 = 玩家，向外放射其**已知关系的全部人物**节点。
- 边：玩家 ↔ 各人物的关系（连接线），线粗/颜色按 `affinity`/`trust`，标注关系标签。
- **动画要求**：
  - 进场：节点**浮现 + 汇聚**到环形/受力布局（transition / spring 动画）。
  - 连线：`stroke-dash` **生长动画**。
  - 交互：悬停/点击节点 → 高亮 + 联动显示该人物档案；节点**可拖拽**；边缘人切换布局。
  - 世界更新后**平滑重排**（属性过渡，而非瞬跳）。
- 视觉效果：SVG 实现（现有 `#relationship-graph` 已有 SVG 基础，扩为全屏切页 + 动画）。
- 数据来源：`WorldSnapshot.relationships`。

---

### 2.9 📓 笔记本（玩家手账 · 切页）

- 玩家**自由记录**自我印象的页面：用户可写"遇见 / 发生"的事。
- 每条记事项：`{ id, created_at, title, body, linked_character_id?, linked_location_id?, linked_event_id? }`。
- **关联**：记录时可链接到某个人物 / 地点 / 事件（从现有数据里选取），便于回访。
- **存储**：**本地 `localStorage`**（命名空间 `iserra.notebook`）。理由：这是玩家**私人物品**，不进世界事实库；轻量、无需后端改动。
- 交互：列表 + 新建 / 编辑 / 删除 / 搜索；点关联跳转到对应人物档案/编年条目。

---

### 2.10 ⏱ 编年者（世界管理 · 抽屉/子页）

从原 `#observer-drawer` 迁移过来的世界管理入口，收在左侧"编年者"分区：

- **世界流速**：时间比例（暂停 / 0.5× / 1× / 2× / 10× / 60× / 自定义）、时钟显示、下一裁判点、状态修订号、裁判次数、模型供应商、自动运行、最后心跳。
- **人物管理**：全部人物档案列表（含筛选）；点击 → 人物详情 / 局部介入。
- **裁判**：执行心跳 / 全局裁判 / 局部裁判（选人选）/ 同步卷宗。
- 仍走现有管理 API：`/clock`、`/adjudicate`、`/heartbeat`、`/history/sync`。

## 3. 数据结构现状（实现前的铺垫）

以下为需要对接的现有库结构（`world_engine/database.py`）：

- `locations(id, world_id, name, kind, resources_json)` —— **无坐标字段**。
- `characters(id, world_id, name, location_id, energy, satiety, money, health, traits_json, goals_json, skills_json, identity, is_player, is_pov, is_core, created_at, updated_at)` —— **无坐标字段**。
- `world_events(id, world_id, tick_id, occurred_at, event_type, actor_id, target_id, location_id, summary, payload_json, created_at)`。
- 迁移方式：`database.py` 内已有 `_migrate_*` 模式（如 `_migrate_identity_column` / `_migrate_health_column`），新列应延续此模式。

## 4. 坐标系统（玩家精确位置 · 核心）

### 4.1 设计目标

- 地图上显示的是**精确坐标点位**，而非"大概到哪里"。
- 坐标是**逻辑坐标**，与当前地图分辨率解耦，换图不坏。
- 全端统一：玩家、NPC、地点中心都用同一坐标系。

### 4.2 坐标系定义（归一化平面坐标）

- 采用**归一化平面坐标**：`x ∈ [0,1]`、`y ∈ [0,1]`。
  - 原点 `(0,0)` = 世界地图**左上角**；`(1,1)` = 右下角；`x` 向右、`y` 向下。
- **像素换算**（仅前端渲染时）：`px = x * 地图宽`，`py = y * 地图高`。
- **数据库只存归一化坐标**；将来换图/改分辨率不影响逻辑值。
- **人性化展示**（可选）：前端把归一化坐标转成"世界经纬"文本 `E …° N …°`（`经度 = x*360-180`、`纬度 = y*180-90`），仅用于显示，底层数据不变。

### 4.3 数据层改动（需要后端）

1. `locations` 表新增：
   - `center_x REAL`、`center_y REAL` —— 该地点在地图上的**中心坐标**。
2. `characters` 表新增：
   - `pos_x REAL`、`pos_y REAL` —— 人物**当前精确坐标**。
3. **迁移**（延续 `_migrate_*`）：
   - `ALTER TABLE locations ADD COLUMN center_x REAL;`（同 `center_y`）
   - `ALTER TABLE characters ADD COLUMN pos_x REAL;`（同 `pos_y`）
   - **回填现有数据**：`characters.pos_*` ← 其 `location_id` 对应地点的 `center_*`（+ 微小随机偏移 `±0.002`，避免同点多人重叠）；`locations.center_*` 需先有值（可由世界创建/seed 时设置，或回填时给一个默认值）。
4. **写路径**：人物移动（`TRAVEL` 行动）更新 `pos_*` 为目标地点中心；创建人物时初始化 `pos_*` = 起始地点中心。

### 4.4 API 改动

- `GET /api/worlds/{world_id}` 返回的 `WorldSnapshot`：
  - `characters[]` 每人带 `pos_x`、`pos_y`；
  - 增加/补充 **`locations` 数据**（含 `center_x/center_y`），或单独提供 `GET /api/worlds/{id}/map` 返回可绘制的点位数据集。
- 建议 `WorldRepository.get_snapshot` 注入：`character.pos_x/pos_y`、`location.center_x/center_y`，以及**玩家当前地点的人物归属**（"附近的人"，现有已能取同 `location_id` 人物，前端据 `pos_x/pos_y` 绘制即可）。

### 4.5 前端渲染

- 地图页用**绝对定位层**覆盖在 `<img>` 上：每个点位 `left = pos_x * 图宽`, `top = pos_y * 图高`。
- "我"用高亮标记；NPC 用圆点 + 关系色（友绿/敌红/中立灰），带图例。
- 点位点击 → 人物档案弹层。
- 显示"当前坐标"文本（可读经纬形式）。

### 4.6 地图区域与资源（建议）

- 现有 `planet-master.png` 为"全星球"视角，点位在超大地图上会很稀疏且不聚焦。
- **建议**：为"主大陆/当前可游历区域"裁剪或生成一张**区域图**（窄视角），点位更密、更直观。若无现成区域图，可先用 `/world-assets/` 下的图；实现方可在规格外自行准备区域地图并挂到 `/world-assets/`。
- 坐标 `x/y` 与**所用图片**的映射需保持一致（若换区域图，坐标需对应新图边界）。

## 5. 前端实现要点

- **单页 + 左右布局**：左侧竖向导航 + 右主区。全部逻辑沿用现有原生 JS + DOM（**不引构建工具 / Node**，保持项目现状）。
- **切页**：`场景`、`地图`、`编年`、`关系网`、`笔记本` 作为"房间"，用一个简单的**视图切换**（显示/隐藏对应 `<section>`，或 hash 路由）；`编年者`子页同理。
- **浮动桌面**：技能/背包/装备/行动为常驻浮动面板，`position: fixed`，收起/展开，不随房间切换。
- **状态同步**：轮询或定时刷新（现有已有 "silent polling + diff" 机制，需保留并迁移）。要求：**刷新时不要重置当前房间/滚动位置**（沿用现有 diff 思路，避免"近期编年每次重连都闪回"问题）。
- **行动结果**：玩家提交行动后，用**即时反馈**（现有 `#action-result`）把"这个世界接受了你的行动"直接回显在场景，再自然落到编年。
- **缓存**：前端资源继续走 `no-cache`（现有中间件）与 `?v=` cache-bust，避免改样式后白底裸文本。

## 6. 分阶段实施建议

建议按依赖顺序推进，每阶段"可跑、可验"，避免一次大改不可控：

- **阶段一 · 骨架与舞台**：整体布局（左导航 + 右主区），场景默认页 + 浮动桌面 + 行动输入栏。让"沉浸舞台"先成立。
- **阶段二 · 地图与坐标**：先做**后端坐标列 + 迁移 + API**，再做前端实时点位图 + 坐标文本。**本阶段是"玩家坐标"落地。**
- **阶段三 · 关系网动画 + 人物档案**：关系网切页 + 进场/连线动画；人物档案弹层（含交谈/攻击入口）。
- **阶段四 · 编年全景 + 笔记本 + 世界管理迁移**：编年可筛选时间线；笔记本（localStorage）；把原编年者抽屉搬进左侧编年者区。
- **阶段五 · 视觉打磨**：配色、字体、动效统一为"书卷叙事"风；响应式。

## 7. 验收要点

1. 打开页面默认落在**场景**，能看到所在之地、时钟、叙述、在场的人、故事卡片。
2. **地图**页能看到"我的精确点位 + 坐标文本"，NPC 点位按关系着色，点击打开档案。
3. **技能/背包/装备/行动**为浮动面板，**不切页**，可随取随用；行动提交后即时反馈 + 落编年。
4. **关系网**有进场/连线生长动画，以玩家为中心，节点可拖拽/点击。
5. **笔记本**可新建/编辑/删除记录，能关联人物/地点/事件，存本地（刷新不丢）。
6. **编年**可筛选、点开原文；**编年者**区能控流速、裁判、人物管理。
7. 轮询/刷新**不重置**当前房间与滚动位置。
8. 移动端（窄屏）布局可用/可滚动（响应式基本可用）。
