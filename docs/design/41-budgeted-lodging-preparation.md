# 各自预算的住宿筹备与真实订房

阶段41把旅途分房前的订房准备接入真实住房规则：双方分别接受自己的房间、总支出上限与期限，再各自询价、付款和报告就绪。40个文件771项相关回归、独立存档真实模型、浏览器完整操作与租住后的分房接续均已验证。正式服务已更新，备份、迁移、健康心跳和正式玩家未被代操作的19项最终核验通过，见 `run/lodging-plans-verification.json`。

## 原旅行、两间房与独立授权

新筹备只在双方真实到达的同一旅行站点提出。原旅行必须有效且处于到站停留，两间房须为本人已认识或眼前可见的真实独立房间，不能相同或互为内外层通道。允许各自经过合法公共前厅。原旅行期限必须覆盖完整房间许可终点；提出与暂停原旅行在同一保存点中完成，失败整体回滚。

`LodgingPlanIntent` 使用独立的 `lodging_plan_choice`／`lodging_plan_intent`，操作为 `propose`、`accept`、`decline`、`cancel`、`quote`、`confirm`、`report_ready`。提出时填写真实 `journey_id`、`own_room_id`、`other_room_id`、`own_budget`、`other_budget`、带时区的 `ready_by_world_time` 与 `required_until_world_time`，以及本人陈述。两个总预算均为0至1000枚的明确整数；筹备期限在未来且早于许可终点，整个安排不超过三十个世界日。

`own` 永远属于提出者，`other` 属于收到提议者；NPC 提出时也采用这套映射。只有收到尚有效邀请的一方可以接受或婉拒，回应不能交换房间、改预算或改期限。单纯台词“愿意”不会补出结构化接受，玩家也不能替 NPC 接受。

接受只授权本人承担约定的房间和本人预算。NPC 接受后可按真实日常排程，用自己的钱包在剩余预算内自主询价和确认，且须保留本人作息计划中的生活储备，最低保留10枚；身体、饥饿、紧急照护、现有活动及已到期约会仍优先。玩家的接受不授权 NPC 动用玩家的钱，NPC 的接受也不代替玩家逐笔确认房费。

## 房主审议、准确报价与付款

订房不是“有牌价就自动租到”。`lodging_review.review` 复用现有住房协商规则，分别核验实际房主、房间出租登记、有效占用、完整租期、金额及房主与该租客的关系，给出接受、反提案或拒绝。它是确定性的规则审议，不是伪造房主模型台词；旅伴的 `accept` 不能代替房主结论。玩家所有的房间仍须由玩家另行明确授权，不能由该规则代为同意出租。

本人 `quote` 根据许可终点计算真实所需租期，并保存住房请求、审议结论、准确总价及报价编号。房主反提案可能高于牌价，不能用预算、牌价或另一人的报价作为最终付款额。报价有效期至多三十个世界分钟，且不超过筹备期限；到期时即不能付款。再次查询有效报价可复用原条款，但核对回执独立记录，不覆盖原审议来源。

玩家 `confirm` 必须同时引用本人的 `plan_id`、本人的 `quote_id` 和准确 `expected_total`。规则重新核对报价是否有效、房主和牌价是否变化、当前完整租期、住房请求及审议条件、本人余额、剩余总预算和完整门路。通过后才按现有 `ContractService` 实际扣本人钱、付给真实房主，并形成限期租约；不是先扣费再把不足许可当成功。

NPC 在自己已接受的总预算与生活储备内，按照同一准确报价路径确认自己的房间。双方付款彼此独立：一人已订到、另一人尚未准备好时，保留已经成立的租约和费用，不伪装成双人原子成交，不替另一人补钱，也不自动退款。

0预算不授权正价采购。本人若已有覆盖整个约定时段的合法许可，可以直接核验并报告，不重复付租；没有完整许可时，不能靠0预算、承诺或虚构免费接待绕过房间规则。既有他人租约不被取消腾房，暂不自动续租、抢房、换房或追踪未知房主位置。需要出租时，必须能够实际当面联系房主，或已有双方接受的信笺联系渠道。

## 真实许可、回站报告与取消

准备就绪不仅是“已经交钱”。核验涵盖指定房间及每层外部通道，许可必须持续至约定终点；实体锁与钥匙仍按原门路规则处理。新筹备不会创建钥匙、开门、移动玩家、授予进入伙伴房间的许可，或购买食物。

本人取得完整许可后，须真实回到原旅行站点室外。双方均在场、可接触且没有移动或活动占用时，才可分别 `report_ready`；一人的报告不能代替另一人。NPC 自主逐步回站并报告，玩家明确选择自己的报告。只有两份独立报告均有效，筹备才变为 `completed`。许可或到场条件发生变化时重新核验，不能沿用失真的就绪状态。

待回应或已确认的筹备阻止提前恢复旅行。筹备完成后原旅行仍保持暂停；进入房间、分房休息、休息后会合，以及恢复旅行，继续使用各自独立选择。本阶段不自动创建阶段40的分房安排或真实休息活动。

提出者可撤回待确认邀请，任一参与者可退出已接受的筹备；期限过后按事实失效。`cancel`、失效或一人拒绝不会撤销已付租约、退回实际房费、停止无关个人活动或自动恢复旅行。原旅行结束、离开原到站安排或一方暂停联系时，本筹备停止；已经成立的个人租约仍独立保留。

## 私有报价、旧接口与审计

`journey_lodging_plans` 保存双方约定、两房、预算、期限及原旅行的真实到站和暂停来源；`journey_lodging_roles` 分别保存个人办理、支出和报告；`journey_lodging_quotes` 保存准确报价、规则审议、住房请求及付款来源。

玩家看到双方已明确接受的房间、上限和期限，以及自己的报价、费用和障碍。伙伴尚未当面报告前，统一展示 `unreported`，不公开其 `offer_ready`、`booked`、`blocked`、报价编号、金额、合同、重试时间或私有原因。NPC 的模型上下文可获得自己的私人回执，但不会收到伙伴尚未报告的细节。NPC 在对话中办理自己的询价或确认，不会由系统把私人结果拼进公开表演或事件编号；成功与失败均不通过公开操作状态区分。NPC 本人愿意说出的台词，与系统自动泄露私人回执，分别处理。

`POST /api/worlds/{world_id}/player/social-choices` 只接收一份玩家本人选择，用玩家逐字原话证据覆盖候选陈述。同请求编号重试返回原回执，不能改成另一选择；同笔准确付款用新的请求编号重取，也不重复扣钱或创建合同，并保留首次付款的 `input_request_id`、原输入与授权证据。新增可空字段缺省时，旧选择回执仍兼容。房主审议事件和确认付款事件不混为一份授权。

`GET /api/worlds/{world_id}/lodging-plans?character_id=...` 返回当前玩家参与的安排；`GET /api/worlds/{world_id}/lodging-plans/options/{character_id}` 只提供本人已知真实房选，不借未知人物枚举房间。人物档案提供新提议，场景“我的订房筹备”提供本人询价、准确付款、报告或退出。已知旧安排的个人操作不要求找到伙伴档案，但不开放隔屋新提议、接受或对话。仅提出、接受和婉拒触发后续 NPC 回应；个人办理不额外生成对话。

旧长期事务接口同样检查参与者权限：玩家不能确认、取消或删除 NPC 的私有住房事务；列表过滤后才分页。属于本筹备的住房请求不能通过旧确认入口绕过个人预算与准确报价绑定，须回到对应筹备办理。拒绝越权不会顺带推进合同或改变钱款。
