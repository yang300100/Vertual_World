# 到站后的室内短休与已有租住安排

本阶段将已经到达的旅行站点与既有室内约会连接。双方分别商量旅行、房间使用、短休和恢复；房租仍从原住房事务单独协商确认，不从一次休息邀请推定付款、入屋或长期居住。

## 已实现的入口

人物档案的“约好下一次见面”新增“衔接到站旅行（可选）”。选择原旅行后，只能提出同一停留站点的单次室内休息，使用已经认识且具备租住、公共或可接待条件的真实房间。时间窗和时长沿用约会规则：五至一百二十分钟休息，最多二百四十分钟的到场时间窗。

提议暂停原旅行并冻结剩余停留，邀请本身不移动任何人、不支付房费。没有合适房间时，先使用原住房协商流程或取得真正许可；不能通过选择房间绕过租约、门锁、实体钥匙及外层通路。

`AppointmentIntent.journey_id` 只用于新建单次室内 `rest`，回应不重填旅行来源。`journey_room_appointments` 保存约会、原旅行、站点、真实到站事件与暂停事件。新邀请与暂停在同一事务内成功或回滚；改期保留原来源，只能留在原停留站点和旅行期限内。

## 同意、房租与真实进门

复用 `AppointmentRoomService` 校验房间、嵌套通路、整段时间窗内的有效租约和接待权。明确 `allow_visit` 只表示本次短时访问，不给予储物、钥匙或长期居住权。有效租住者可在允许的时间窗内表达本次接待，房主或旧常规许可不能覆盖当前租客的房间管理权。

接受约会不自动进屋。玩家逐扇门开门、进入；NPC 按自己的真实日程逐门赴约，在未到时间或接待者未在场时等候。双方实际进入同一指定房间、处于时间窗内且当前条件允许后，玩家选择“到场后开始约定的相处”。

活动完成前先核对接待条件：即使下一次心跳直接跨到结束，权限或租约变化仍会中断共同短休，不能先记为完成再跳过检查。已经消耗的时间保留；没有额外扣房费。各人仍可按真实门路离开，不因许可失效被传送或锁在屋内。

## 返回旅途与生命周期

待回应、已确认或正在进行的关联室内安排会阻止恢复旅行。短休完成不自动离屋或出发：玩家自己离屋，NPC 按本人日程离开，双方回到原室外站点后，再独立确认恢复并选择下一程。

原旅行失效时，尚未确认的邀请撤销并保存取消事件；已经明确同意的室内安排沿自身约会生命周期履行，正在休息的人不会被强制退房。取消、失约、改期及重复请求继续复用原有记录和幂等回执。

## 提示与验收

NPC 只接收本人可知的房间与租住接待事实、已经表达的本次许可和当前约定。最相关往事与当前同意固定保留，其余完整历史按原预算补入，不删除原始记忆，也不扩大 8192 输入上限。

独立模型验收沿用先前已真实探索的测试地图，房间作为明确登记的隔离内容存在。住房使用原模型协商与玩家确认流程，实际支付租金；本次新旅行和室内短休由真实模型独立接受。双方通过真实门路入屋，实际休息，再分别离屋、同意恢复与返程。早期存档的隔离前置条件继续单独标注，不混作本次真实模型选择。

证据保存在 `run/journey-rooms-model-proof.json`、`run/journey-rooms-ui-proof.json` 和 `run/journey-rooms-verification.json`。正式存档不植入测试房间、租约、关系或行程。

364 项相关回归通过，新增室内旅行场景为 29 项；最新提示与室内专项 50 项另行通过。浏览器验证了旅行表单切换改期会解除原限制、玩家逐门入屋、NPC 等候与自行进门、到场开始十五分钟休息、双方各自离屋、明确恢复和实际返程。页面无脚本错误，截图接口报错和超时，保存页面文字回执 `run/journey-rooms-ui-completed.txt`，不冒充已取得截图。

正式存档已备份，新表、健康接口、前端资源版本与后台心跳已核验。正式关联记录、测试房间和测试人物数均为零；没有代玩家租房或接受旅行。正式提示快照估算为 8013 token，长隔离场景为 8192，保留原输入上限。

本阶段实现室内短休与已有租住衔接。完整过夜、自动订房、替另一人付款、多人及共乘仍未实现。
