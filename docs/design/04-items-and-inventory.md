# 物品实例、小背包与所有权流转

状态：基础物品实例、两格默认背包、堆叠消耗、真实库存交易、所有权、装备限制和库存审计已实现。
2026-09-13 补充：房间储物容器、资源补给、配方生产、工具预留/磨损和限额备料采购已在文档16、21接入。
赃物状态、独立仓库/车辆货箱、食品新鲜度及复杂生产物流仍属于目标设计；详见[完成度核对](implementation-audit-20260913.md)。

## 设计目标

普通人物只能随身携带少量物品，使每件物品都有选择成本、来源和去向。背包不是人物全部财产，而是当前随身携带集合。

## 容量建议

| 人物情况 | 建议容量 |
|---|---:|
| 没有容器或口袋 | 1格 |
| 普通人物 | 2格 |
| 商人、旅行者 | 3至4格 |
| 车辆、马车 | 使用独立货箱 |
| 住宅、店铺、仓库 | 使用地点储物，不属于随身背包 |

第一阶段推荐普通人物2格。小型同类消耗品可以少量堆叠；普通工具、武器、信件和独特物品各占1格。

## 随身物品与其他资产分离

```text
人物资产
├── 随身背包
├── 穿戴装备
├── 住宅储物
├── 店铺库存
├── 仓库货物
└── 车辆货箱
```

穿着的衣服和已经装备的武器使用独立装备位，不占普通背包格。金钱第一阶段继续作为独立数值，不占格。

## 物品类型与物品实例

### 物品类型

描述“面包是什么”：

```json
{
  "item_type_id": "bread",
  "name": "面包",
  "category": "food",
  "stack_limit": 3,
  "slot_size": 1,
  "usable": true
}
```

### 物品实例

描述“林澈手里的这一批面包”：

```json
{
  "item_instance_id": "bread_instance_018",
  "item_type_id": "bread",
  "owner_entity_id": "npc_lin",
  "container_type": "character_inventory",
  "container_id": "npc_lin",
  "quantity": 2,
  "condition": 76,
  "acquired_event_id": "event_bought_bread_01"
}
```

独特物品可以保存：

- 耐久度或新鲜度。
- 制作者和来源地点。
- 当前合法所有者和实际持有人。
- 是否被偷窃。
- 是否隐藏。
- 特殊能力和相关历史事件。

## 背包结构

```json
{
  "character_id": "npc_lin",
  "capacity_slots": 2,
  "slots": [
    {
      "item_instance_id": "bread_instance_018",
      "quantity": 2
    },
    {
      "item_instance_id": "letter_007",
      "quantity": 1
    }
  ]
}
```

背包满时，人物不能凭空获得新物品，必须选择：

- 放弃拾取。
- 丢弃已有物品。
- 立即使用物品。
- 交给同伴。
- 返回住所或仓库存放。

## 物品动作

第一阶段建议支持：

| 动作 | 含义 |
|---|---|
| `pickup` | 从当前位置拾取物品 |
| `drop` | 把随身物品放到当前位置 |
| `use` | 消耗或使用物品 |
| `give` | 无偿交给同地点人物 |
| `trade` | 经过价格和所有权校验交易 |
| `steal` | 尝试秘密转移所有权 |
| `equip` | 移入装备位 |
| `unequip` | 从装备位移回背包 |
| `store` | 存入有权使用的地点储物 |
| `retrieve` | 从地点储物取回 |

每个动作都必须验证：

- 物品是否真实存在。
- 物品是否处于人物可触及的位置。
- 人物是否感知到物品。
- 背包是否有足够容量。
- 人物是否拥有或有权使用该物品。
- 物品是否允许携带、堆叠、使用或交易。

## 与特质和状态联动

```text
节俭特质
+ 当前严重饥饿
+ 背包中最后一块面包
+ 附近没有补给
= 立即吃掉或继续保存的真实选择
```

模型只能选择当前背包和环境允许的动作，不能凭空生成工具、食物或钥匙。

## 事件和库存日志

购买面包时分别记录：

世界事件：

```text
林澈从晨星广场的商人手中购买了两块面包。
```

库存变化：

```json
{
  "character_id": "npc_lin",
  "source_event_id": "event_buy_bread_01",
  "operation": "item_added",
  "item_instance_id": "bread_instance_018",
  "quantity": 2,
  "slots_before": 1,
  "slots_after": 2
}
```

人物状态变化：

```text
金钱：9 -> 6
```

三者通过同一个 `source_event_id` 关联。库存日志用于精确审计，重要交易、盗窃和独特物品流转进入世界事件。

## 主视角认知边界

观察者不能自动读取其他人物背包。只有以下情况更新知识图：

- 物品公开佩戴或携带。
- 对方主动展示。
- 交易中出现。
- 搜查成功。
- 偷窃或战斗过程中发现。
- 从可靠消息来源获知。

隐藏物品仍存在于客观世界，但不进入观察者知识图。

## 物品与高级事件

普通食物被偷通常是人际或地方事件。王国印玺、世界武器核心等独特物品虽然在小地点丢失，却可以拥有5级潜在影响，并沿因果链升级为地区或世界事件。
