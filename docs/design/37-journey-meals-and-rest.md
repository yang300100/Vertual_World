# 旅途中的到站用餐与休息

本阶段让双方在已到达的旅行站点暂停原行程，另行商量共同用餐或休息。旅行同意、供餐安排、共同活动和恢复旅行分别结算，不能将其中一次同意扩成其余权限。

## 操作与真实状态

人物档案中，正在停留或已暂停的行程提供“暂停行程，邀请到站用餐”和“暂停行程，邀请到站休息”。玩家选择一至一百二十个世界分钟；用餐可选择各吃自己的食物，或本人提供双方各一份随身食物。

`SharedLifeIntent` 的新邀请可以带 `journey_id`，只允许 `meal` 或 `rest`。必须是原旅行的双方、真实到站、同一室外站点二十五米内、彼此二十米内，并已停止移动；途中、集合前、其他人物、过期或结束的旅行均不能借用这个入口。

邀请与旅行暂停在同一保存点内提交。暂停冻结原站点剩余停留，保留真实位置与路线；邀请本身不开始活动、不买食物、不扣钱、不消耗食物。对方明确接受后，再核验当前行程、真实站点、本人状态、日程、食物和背包条件，复用既有共同生活事务开始活动。

请客仍使用邀请者真正持有的两份食物，分别记录提供者、接受者、转交和进食；不足时整体拒绝，不采购、不留下半次转交。休息按实际世界时间恢复精力。已经吃掉的食物和经过的时间不会因退出退回。

## 独立同意与失效处理

共同活动结束、被拒绝或中止，都不会自动恢复旅行。待回应或进行中的到站活动需先处理，才允许请求恢复。恢复仍由一方请求、另一方明确使用原行程恢复选择；之后玩家另行选择出发。暂停期间不会把用餐休息时间冒充已经补完原约定停留。

到站邀请的期限取一天与原旅行期限的较早值。原旅行结束、到期、停留站点失效或改变时，尚未开始的关联邀请撤销，保留取消事件并释放后续邀请；已经独立同意并开始的共同活动仍按自身规则继续或中止。结束活动的记忆不谎称原旅行仍处于暂停。

`journey_breaks` 将相处编号关联到原行程、站点、真实到站事件和暂停事件，外键保持来源一致。普通用餐和休息不自动关联旅行；回应只引用真实相处编号，不能改变原路线、供餐方或站点。旧幂等回执忽略新增的空旅行字段，非空来源仍参与核验。

## NPC 上下文与预算

普通交谈、信笺和主动联系沿用同一结构，可独立选择是否接受。本人上下文保留正在等待回应或进行中的相处、原行程状态和最新已完成事实。较早活动的完整原话按原有预算补入历史资料，原始记录不删除；不扩大 8192 输入上限，不裁掉当前选择或知识边界。

## 验收与范围

真实模型与浏览器证据分别保存在 `run/journey-breaks-model-proof.json`、`run/journey-breaks-ui-proof.json`，回归及正式服务核验见 `run/journey-breaks-verification.json`。

独立评测沿用上阶段已真实探索并完成往返的测试地图。早先旅行的初始同意属于明确标注的隔离前置情境；本阶段新旅行、到站用餐、休息及恢复均由真实模型本人候选结算，不替模型接受。用餐消耗两份真实购买的食物，休息和补完停留均推进实际世界时间，最后实际返程。

330 项相关回归通过，其中最新核心回归 100 项、共同生活等回归 230 项。浏览器通过正常表单完成请客、休息、恢复请求与返程，两个活动均完成并留下两份进食回执，未发现页面脚本错误。

正式存档已备份并安装新表，健康接口与后台心跳通过；正式旅行、到站活动、双方确认关系及测试人物数量未被验收改动。正式提示快照估算为 7735 token；含真实旅行、用餐、休息和恢复历史的隔离提示为 8190，均在原 8192 上限内。证据文件保留实际原始模型选择与早先未完成的尝试，不把空白返回或被规则拒绝的候选算作成功。

本阶段覆盖同层室外徒步的到站相处。室内住宿、自动订房、旅途中采购、多人及共乘仍未实现，不因旅途关系授予房间、财物或身体权限。
