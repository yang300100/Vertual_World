# 语义地形与现实路线规划设计

状态：候选数据阶段；尚未接入真实世界数据库。

## 权威边界

- 经纬度是位置真相源，地图像素不是。
- 当前自然地图是视觉与宏观地理参考，不直接等价于海拔、水深、坡度或可通行性。
- 自动生成结果一律标记为 `candidate`；只有审核通过的版本才能导入运行时。
- 地形与路线规则由本地代码裁决，模型只能提出目的地或偏好，不能越过不可通行边。

## 候选地形包

北方主大陆试点目录：`docs/worldbuilding/maps/navigation/northern-main-continent/`。

| 文件 | 含义 |
|---|---|
| `metadata.json` | 坐标边界、分辨率、编码、来源哈希和统计摘要 |
| `elevation.png` | 16位无符号高程；海平面为0，陆地单位为米 |
| `water-mask.png` | 0=陆地、160=内陆水体/候选河流、255=外海 |
| `slope.png` | 0至255线性映射到0至90度坡度 |
| `surface.png` | 带调色板的地表类型栅格 |
| `waterways.geojson` | 已确认命名关系约束下的候选河流中心线 |
| `roads.geojson` | 候选道路中心线及道路等级 |
| `crossings.geojson` | 桥梁、渡口、港口、山口等跨越门户候选 |
| `route-graph.json` | 用于分层寻路的高层节点和边 |
| `movement-rules.json` | 移动类型、坡度限制和地表速度倍率 |
| `audit-overlay.png` | 供人工审核的地形、河网、路网和节点叠加图 |

第一版坐标边界固定为经度 `[-170, 0]`、纬度 `[0, 72]`。这只是北方主大陆区域图与世界坐标的候选映射，审核时可以调整；调整后必须整体重新生成，不能局部平移数据。

## 地形采样接口

未来运行时按任意经纬度派生：

```json
{
  "elevation_m": 184,
  "is_water": false,
  "water_kind": null,
  "surface_type": "grassland",
  "slope_degrees": 3.2,
  "road_id": "forge-adde-east-road",
  "road_type": "trade_road",
  "speed_multiplier": 1.45
}
```

派生值不重复写入人物表。人物只保存精确经纬度；进行中移动保存路线、当前路线段和已行进距离。

## 通行规则

- `land`：不能进入外海；跨越不可涉水河流必须经过桥、渡口或浅滩门户。
- `ship`：只能在可航行水体和港口转换边上移动。
- `flight`：可跨越海洋、河流和高山，但仍受载具升限、天气、能源和航程约束。
- `underground`：第一阶段只允许沿已登记隧道/矿道边移动，不允许任意直线钻地。
- `water`：供小艇、筏和两栖载具使用；是否能进入外海由载具能力决定。
- 普通陆行遇到超过35度坡面时视为不可通行；20至35度显著减速并优先寻找山口。
- 道路倍率只在人物实际投影到道路缓冲区内时生效，离开道路后立即恢复地表倍率。

基础公式：

```text
实际速度 = 载具基础速度
         × 地表倍率
         × 道路倍率
         × 坡度倍率
         × 天气倍率
         × 人物状态倍率
```

## 分层寻路

1. 在局部栅格上从起点连接到最近可用道路、港口或山口。
2. 在 `route-graph` 上进行跨区域A*。
3. 在终点附近重新进入局部栅格。
4. 规划结果保存为经纬度折线；心跳只沿折线推进，不重复搜索整张地图。
5. 断桥、洪水、封路或载具切换使当前边失效时才重新规划。

## 2核2GB约束

- 生成器只在开发机运行；服务器只加载已生成数据。
- 不将每个像素拆成SQLite行。栅格按区域文件/压缩块读取，高层路网存SQLite节点和边。
- 后续使用SQLite RTree索引道路、河流、桥梁和区域边界。
- 每次心跳只采样当前位置和当前路线段，不执行全图像分析。

## 审核顺序

1. 审核海岸线和外海掩码。
2. 审核西部山脉、南部高地与主要山口。
3. 审核锻河、镜河、赤泉河、阿德河的中心线。
4. 审核锻谷城—澜誓城—东澜港主路及支路。
5. 审核桥梁、渡口、港口和可航行河段。
6. 审核通过后才设计数据库迁移与正式路线规划器。
