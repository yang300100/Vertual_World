# NPC 日程逻辑与内容填写交接

2026-09-10。用户要求先完善代码逻辑，具体世界内容交由更低成本的模型填写。
本轮不新增正式人物、房间、配方、商品或工资资金。

## 本轮实现

- 新见面约定可以包含带时区的 `meeting_world_time` 和 5–240 分钟的 `meeting_minutes`。
  只有在该时间窗内、同地点的真实双方交谈才完成约定。没有明确时间窗的旧约定保持旧语义。
- 接受和确认时都核对时间格式、有效地点、参与者、当前活动、行程和已有约定。
  冲突说明不透露其他约定的参与者及内容。
- “约定改期”复用已有的提出、模型回应、玩家确认流程。条款包含 `appointment_id`、
  `expected_revision`、新时间和时间窗；地点、参与者及托管报酬保持，改期不重复扣款。
- 确认时复核原约定修订号。两个基于旧时间的改期提案不能相互覆盖。
  已经逾期的约定可以重新商议，但历史逾期事件与关系后果不回滚。
- NPC 为赴约预留路程及准备时间，普通工作和制作不会占用已确认约定的赴约时间。
  当前活动结束、行程抵达、经过房间入口和临近出发时可在同一小时内重新安排。
- 严重饥饿、低精力或伤势可打断 NPC 的耗时工作/制作；已支付体力保留，材料和工资
  按原中止规则退还。已经在做的休息不因低精力反复中止。
- 日程出现风险时按状态变化去重记录，玩家得到事实提醒；NPC 可以通过原主动联系
  队列选择是否商议改期。提醒不等于 NPC 已经发言，也不等于改期已经执行。
- 主动等候会在玩家明确的见面开始时间停下。界面可查看当前安排、提出新见面时间、商议改期。

## 数据与兼容

`appointment_windows` 保存当前时间窗和修订号；`appointment_revisions` 保存确认改期的
前后时间及来源请求；`npc_schedule_assessments` 保存日程判断，避免同一风险每分钟重复通知。
新增表按需记录，不给旧存档猜测或批量创建日程。原世界时间和在途活动不重置。

路程预估使用现有行程预计抵达时间和地理距离；新路线实际通行时间可能更长，随后会重新
判断是否迟到。这不是完整交通预测，不自动改变条款、转移角色或编造抵达事件。
当前只支持单次见面改期，不自动重排全部人生目标、改工作合同或批量管理周期性日程。

## 给内容模型的材料

[填写说明](../content/life-content-authoring.md)可直接交给内容模型。
`scripts/prepare_life_content.py` 按明确地点只读导出目录、四种真实 JSON Schema 和空草案模板，
并支持草案结构/引用检查。没有导入、改库、自动确认或模型调用功能。

先填物品类型、资源来源、外层房间和工资账户，确认后重新导出真实 ID，再填配方和内层房间。
角色私人记忆、提示词、密钥和完整存档不进入交接材料。内容模型不能通过新增字段获得引擎能力。
