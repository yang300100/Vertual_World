# 21 生产准备与工具消耗

让居民的生产活动建立在真正拥有的材料、工具和时间上。代码负责条件与结算，内容模型只填写经审核的规则。

## 本轮规则

- 制作和修理配方支持 `tools`，每种工具占用1件，完整工序磨损 `wear`（1–100）。缺少工具、所有权不符或完好度不足时不扣材料、不启动活动。
- 工具不能重复声明，也不能同时作为消耗原料；修理目标不能同时作为工具。检定工具与通用工具重合时只占用1件。
- 开始时拆分并预留真实工具，无法在活动中转卖或重复使用。所有工具要求、材料、成本冻结在本次活动快照中。
- 完成时扣完整磨损，修理失败也扣；中止按实际世界耗时占比向上取整，零耗时中止不磨损。工具可损坏至0但不被删除，仍可领取并按已有修理规则恢复。
- 剩余原料、目标、工具均留在原地点的成果区，背包满时不丢弃。结算写入结果、事件和库存审计，重复结算不再扣库存或发产物。
- 旧配方无工具列表继续可读；旧修理检定工具新开工默认磨损1。升级前已开工且没有磨损快照的任务沿用原约定，不追扣。

## NPC 的准备行为

在作息指定地点真正抵达、未开始活动且仍有时间时，核对本人随身原料和可用工具。每15世界分钟最多取得1份短缺物资，留出整理间隔和完整工序时间；不提前产出。

优先收取当前位置已登记的公共或本人资源，沿用精力、数量和容量限制，并为后续工序保留精力。其次向同地点、同房间、100米内的现有商人购买指定物资。双方移动中不能交易；卖方只能出售本人随身真实库存，不能动用预留工具或玩家物品。采购采用现有登记价格，不生成议价台词。

制作时段新增 `supply_purchase_budget`：默认0，每次实际时段累计消费不得超过预算，同时人物余额不能低于 `income_reserve`。准备记录 `npc_routine_supplies` 保存时段、时间、物资、来源事件和支出，重启不会重置预算与间隔。修订/停用后的库存继续属于人物，不退款、不删除材料。

预算和采购详情只在作者接口展示，公开作息不包含这些私人财务信息。缺料暂缓的原因通过现有作息执行记录保留。

## 作者与玩家界面

作者配方表单支持工具 JSON，审核展示每种工具的占用与磨损。作息 JSON 支持采购预算，读取已有作息同时可查看近期准备记录。玩家活动预览展示工具要求，结果展示实际磨损，领取区展示完好度。

`scripts/prepare_life_content.py` 导出更新后的真实 Schema，并校验工具引用、重复和原料冲突。填写规则见[内容说明](../content/life-content-authoring.md)。正式商品、配方、资源和作息仍由用户选择模型填写、审核后登记。

## 明确边界

当前准备是每次心跳中的一份合法获取及15分钟重试间隔，还不是可中途打断的连续采集工序；不替代完整劳动计时模型。只在当前制作地点备料，不全知搜索异地库存，不瞬移采购。不包含食物腐败、细分营养、多人工序、火候、通用制作检定、职业晋升或动态市场。

地图核对的参照工具仍使用原检定逻辑，本轮不改变地图系统。没有向正式存档自动填内容，不调用真实模型，不提交或推送 Git。
