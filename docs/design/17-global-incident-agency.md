# 全球灰幕与 NPC 自主应对

## 验收范围

使用 `docs/world/locations.json` 中三个远隔城市作为地理依据，建立独立缩小世界。火山灰损坏全部登记粮场的防灰原件，暂停新增粮食产量，保留已有口粮。六位 NPC 的职业、技能、库存和联系人地址是初始事实，事件注入不写救灾目标、执行步骤或完成结论。

正常心跳和到期的 `scheduled_12h` 规则裁决推进全流程。离线测试阻断 HTTP 客户端网络发送；演示显式使用规则决策器并关闭世界代理，不加载 `.env`。

## 因果与知情边界

- 作者注入全局事实；NPC 只在当地观察范围内获知损坏迹象。
- 知情维修者依据自身技能和可见库存采纳维修目标。缺材料、工具或检定工具时生成求助。
- 维修者依据本人已有且有效的联系人地址走访、实际交谈；运料人听到求助后依据自己的库存决定是否贡献。
- 每次只执行一个规划步骤；行旅、社交、交付、维修和领取通过现有领域服务结算。拒绝交付不代表物资已经送达。
- 多种材料和多轮维修可产生新的求助与配送；目标去重同时比较来源和谓词。
- 求助、目击和恢复消息排除跨地区后台传闻。传递须满足实际接触条件，并保存来源事件。

## 完成与生产核验

每个地点要求当前目击对应的维修目标完成，且存在关联到实际维修活动的成功结束证据。原件耐久、数量、归属、领取状态、保管人生存及在场条件均需满足。

全局事件仍活跃时，已经恢复的地点每次心跳重新核验；再次失效会重开受阻区间并要求新一轮证据，不能用旧恢复记录宣告全局完成。只有全部登记地点当前恢复才写一次全球解决事件。

`incident_disruptions` 保存各段受阻区间。经济再生扣除这些区间的并集，恢复后不补发灾害期间产量，再次受损也不追溯抹去中间正常生产。初始化包含已有事件数据的区间迁移。

## 复现与边界

运行 `.venv/Scripts/python.exe -m scripts.demo_global_incident`，检查新输出目录的报告和数据库。报告保存目标动机、行动结果、消息传递、恢复证据、事件因果与恢复后的真实再生事件。

当前设施模型使用由 NPC 持有的维修原件，尚未建立固定设施安装系统；当前灾害类型限于已登记生产资源与维修配方的协作恢复。模型自主开放式救灾推理以及任意灾害的通用解决能力不在本次验收结论中。
