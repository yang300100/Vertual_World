# NPC 生动对话管线实施方案

状态：第一至第四阶段的基础闭环已实现。目标是吸收 SillyTavern 的角色卡、动态上下文、相关记忆、知识激活与
预算管理思路，同时保持 SQLite 世界状态、人物认知和规则裁决为唯一权威。

2026-09-07 补充：各玩家交互渠道统一使用 `roleplay.py`，真实原话按 user/assistant 消息发送，
最近完整问答优先保留，并增加末尾输出提醒和接口 JSON 模式。源码分析与实际 prompt 见
[SillyTavern 角色扮演复查](15-sillytavern-roleplay-review.md)。

## 已实现：单人物核心闭环

```text
玩家输入
  -> 本地识别明确对话对象
  -> DialogueContextAssembler 组装角色、场景、关系、待办、记忆与知识
  -> 按 token 预算裁剪可选段
  -> 目标 NPC 一次结构化模型回复
  -> 禁用术语与 Pydantic 校验
  -> ActionService 规则结算
  -> 同一事务记录事件、双方原话与 NPC 亲历记忆
```

- 明确目标和连续追问不再先调用玩家行动规划模型。
- 当面、联系人交换、远程信笺和长期事务复用同一上下文结构。
- 角色卡增加语言风格、主动性、称呼习惯和最多四条语气示例。
- 记忆按本轮主题、重要度和新近性排序，不再固定读取最高重要度三条。
- 一小时以前的旧对话可以按话题召回；最近一小时仍优先使用原话。
- 静态知识只自动采用 `always_include` 的通用知识/护栏；动态知识先按人物和地点过滤。
- `budget_trace` 记录强制段与各可选段的估算 token。

## 已实现：会话状态与分段摘要

已新增只保存派生信息的 `npc_conversation_episodes`：

```text
session_id
first_turn_index / last_turn_index
summary
topic_entities
open_questions
open_commitments
source_hash
created_at
```

原始回合永远保留。当前使用本地提取式摘要，只覆盖明确回合区间，不采用“旧摘要反复重写”
的滚动方式，避免长期漂移。每段保存来源事件和 SHA-256；失败时不影响原始对话和世界推进。

## 已实现：结构化世界信息激活

为公开知识增加世界、地区、人物、组织、时间有效期和事件类型范围。运行时顺序为：

```text
权限与世界范围硬过滤
  -> 人物/地点/事件实体匹配
  -> BM25 或本地向量相关度
  -> 重要度与有效期
  -> token 预算
```

作者隐藏资料不能通过相关度越过权限过滤。NPC 在台词中提出的新说法只能成为带来源的
`character_belief` 或 `local_claim` 候选，不会直接成为客观事实。

## 已实现：多人场景基础闭环

发言人由本地调度器选择，优先级为玩家指定、明确点名、职责/目标相关、关系和发言冷却。每轮
默认最多两人发言；后一位能看到前序回复。模型只为已选择且100米内在场的人物生成台词，全部
生成成功后才原子写入事件、原话与记忆，不能自行召唤未在场人物。

## 验收指标

- 明确对话每轮只进行一次 NPC 模型生成。
- 可选资料按配置预算裁剪，强制安全段不被可选历史挤出；强制资料本身超量时明确报告
  `over_budget_tokens`。完整请求的 system 和消息包装开销另行估算。
- NPC 跨一小时后仍能从亲历记忆或旧对话中召回相关内容。
- 所有社交渠道使用相同角色卡、记忆与知识权限。
- 普通 NPC 不读取 `author_hidden`，远程信笺不获得现场感知。
- 模型失败、非法 JSON 或禁用术语不会写入台词、关系或世界事实。
- 多人物场景中未在场、未选中或连续冷却中的 NPC 不发言。
