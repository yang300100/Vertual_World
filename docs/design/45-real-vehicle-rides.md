# 真实载具与共乘

本阶段推进总目标 G7。当前实现同层、单目的地、无有限燃料定义载具的正常共乘流程；G7 整体仍未完成。

## 真实状态与登记

旧 `vehicles` 的归属和速度不能证明载具在哪里、能坐几个人。新增 `vehicle_states` 保存经确认的位置、空间层、安全站点、含驾驶者的容量与累计里程。未知的旧车不自动获得座位，也不自动出现在车主身边。

`vehicle` 严格登记先形成 proposed，编年者明确确认后才生效。人物不能通过意图造车、扩座或补燃料。位置来自同世界有效正式地点及该地点的非未来来源事件；船、水下载具、飞行和地下交通分别要求已登记的适用站点。旧车只允许补尚未知的物理状态，原归属、名称、类型、速度和 metadata 保留，已有状态不能借补登记重新定位。

## 逐人的有限选择

`vehicle_rides` 冻结载具、完整名单、控制者、起终点、容量、期限和停止政策；`vehicle_ride_members` 分别保存每个人的接受、婉拒、登车、下车与来源事件。

`RideIntent` 支持 propose、accept、decline、board、depart、request_stop、disembark、end。提议只表达提议者本人的意愿，尚未回应的受邀者仍可独立活动。接受不等于登车，每个人都须自己 board。所有成员有效接受并登车后，原控制者另行 depart。驾驶权仍取现有车主或有效租客规则，不能因获邀乘坐就取得驾驶权。

新提议要求眼前同层近距成员和真实已到访的地点。登车要求本人实际到车旁，同层、室外、静止且无其他冲突活动。末座与同人多约由事务及唯一索引保护，失败回滚不破坏旧安排。原名单有人婉拒时保留其原回应，不自动删人后出发。

## 路线、停靠与边界

控制者的一条 `character_movements` 作为载具唯一的实际路线，并由 `vehicle_rides.movement_id` 绑定。每次先更新车辆和全部在车乘员的真实位置，再检查分离与记录事件；不会把逐人写库顺序解释成一次假重逢，也不会为每个乘客另造驾驶路线。

途中 request_stop 表示按原条款请求在原安全目的地停靠。抵达不自动下车；disembark 只操作本人，必须满足真实静止和安全站点条件。乘员不能通过独立移动、取消、换交通工具、方向输入、走近人物、进屋、原地工作或跨层入口绕过绑定。

出发前核对原期限、预计真实抵达、租用剩余时间、身体和各自原承诺。途中驾驶权、车辆状态或身体不再允许驾驶时，保留实际位置及全部乘员并挂起路线；租约到期不会把乘客直接改成徒步或放到海空中。未定义有限燃料时不凭空发资源；存在有限燃料定义但尚无结算规则的载具明确拒绝出发。

## 读取、渠道及证据

`GET /rides` 仅返回玩家本人的安排，`GET /rides/options` 只列眼前有确认物理状态的车辆、近距人物和本人已到访地点。写入口沿用 `POST /player/social-choices` 的原话证据、请求幂等与 `ride_choice`，NPC 则通过普通对话、文字渠道和主动联系的 `ride_intent` 表达自己的候选选择；远程不能登车和驾驶。

当前完整条款及逐人状态进入 NPC 提示，重复字段压紧，旧共同经历按历史预算选入。本人偏好和当前承诺保留，8192 输入硬门禁不提高。未来提议、来源、知识和成员状态不能提前展示；已下车或走远的人不会取得车辆实时位置或后续远处登车事件。重复提交返回本人原业务回执，不给旧事件或他人的同意补上新玩家原话。
