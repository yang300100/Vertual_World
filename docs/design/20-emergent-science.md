# NPC自主科研与科技生长

科研默认关闭。迁移只新增来源表，不产生科技、不启动模型调用。NPC自行提出问题、提交严格程序，进行真实工艺、量器检验、传统对照与两次独立重复。认证后的方法仍需真实实物、供能、劳动与具体版本；依赖来自实际方法调用或可追溯产物，不读取人物声称的父科技。

自然模型是有限近似。它支持常见材料的热传递、结构变化、孔隙、颜料固着等响应，不代表任何自然语言发明都可执行。没有预登记科技名称、配方、研究路线或待发现清单。已有传统陶片、铁件、染色纤维仅用作原世界能力对照。

科研程序新增可选 `phase`，默认 `execute` 保持旧程序兼容。NPC 可提交 `phase=preview`，以同一执行入口检查当前可开始的阶段；SQLite 保存点内的程序、候选、材料、燃料、工具占用、劳动和事件全部回滚，仅向本人保存检查回执。检查不推进世界时间，不提供模拟读数、临时产物编号或工艺答案。`checked` 仅表示当前检查通过，`ready_to_start` 仅表示当前阶段能够开始，`deferred` 表示必须等待真实前置结果后才能检查；都不是实验完成或科技认证。NPC 自行修改并再次提交 `phase=execute`，实际执行重新校验当时的条件，不能把旧预检当作执行许可。相同程序与相同回执去重；回执不作为新实测取得调度优先级。

调度优先真实新证据，其次给予预检作者一次本人跟进机会，再轮到尚未判断者。机会按本人真实证据阶段持久记录在调用账中，请求预约即消耗；再次预检、改措辞、空执行、解析拒绝和进程中断都不能返还。本人取得新的真实证据或实际送达的方法后才进入新阶段。预检回执始终不是科学实测。

科研世界心跳按真实事件边界推进，结算劳动、消息与材料，再按需调用人物。科研API显式开启时，引擎其他模型后端关闭。单次运行12次、累计200000 token、输出8192、技术重试0；事先原子预留完整输入和输出，未知用量保留全部预留。普通时钟和饥饿不触发反复调用。停止新请求后，人物已经提交的有限程序继续依正常耗时结算。

`scripts/demo_science.py`用只读SQLite backup建立包含WAL的一致性副本，仅在副本迁移。保留原人物身份、技能、目标、关系与记忆，准备有限工坊与既有熟人/同地渠道。初始无科技和研究程序。冻结源码、世界观、自然规则、初始实物、模型配置和预算。运行配置固定240世界小时、4800心跳观察上限，不承诺突破。

正式运行前必须完成离线验收和独立整体审查，验证摘要保存在计划执行目录。运行使用冻结数据库包装；每个正常事务记录状态摘要和前项链，普通外部库存、配置或源码改动会停止本轮。此为自主性审计机制，并非对抗能任意改写整个数据库及审计文件的攻击者。恢复不会清空调用账目或重发未知请求。

命令使用原虚拟环境解释器，依次执行：

```powershell
python scripts/demo_science.py --source-db C:/Users/14261/Desktop/Vertual_World-main/data/world.db --world-id eb06b024-61f8-4ea8-b4e3-2695e4ccebf6 --output run/science/新时间戳 --prepare-only
python scripts/demo_science.py --output run/science/同一时间戳 --run
python scripts/demo_science.py --output run/science/同一时间戳 --export-only
```

准备和导出不请求模型。运行不调用生图，不写原存档或.env。已停止会话不能恢复付费调用；运行锁须核对进程，禁止开第二份并发实验。

脚本从当前项目根目录读取 `.env`；可通过 `--verification 路径` 指定本次离线验收与独立审查记录，默认路径保持兼容。新的累计实验额度须由用户明确指定，不能因旧运行路径不可用而自动清空账目。

已停止的完整实验导出时，会把原冻结源码和设定保存到存档目录的 `frozen-files/`，索引为 `frozen-files.json`。后续源码修复后，跨轮费用仍核验原数据库封印和这些原文件的冻结哈希；任何原文、费用或状态篡改仍拒绝。归档只能用于已停止记录的历史证据和费用核验，运行中的源码变更不能通过归档绕过冻结；旧停止会话也不能因此恢复付费调用。

玩家可从“科研卷宗”查看只读科技图、候选、预算与原始过程。`GET /api/worlds/{id}/science`、`technologies`、`technologies/graph`、`technologies/{科技id}/process`、`science/candidates`不调用模型。全局科技图供观察者查看；NPC上下文只含本人知识、实测和真实收到的方法。

导出提供处理过程、全部人物与通信、科技图JSON/SVG、每项突破原始记录、编年、费用、冻结和最终验收。至少3项已验证非预置能力、1条实际依赖及真实后续复用才通过。预算不足或接口失败如实报告，不提高额度，不用离线固定程序成果代替真实NPC判断。

## 原理科研中的魔法领域

原理科研另采用人物提案与独立原理评审，不要求复现上述实物认证流程；研究达成与实际应用分别记录。新提案须指定 `physical`、`magic` 或 `hybrid`。科技节点仍为可复用知识或工艺，具体器具与施法辅助设计放入衍生发明。领域不预置科技名称，也不自动生成技术联系；前置、改进、互补关系沿用逐项因果评审。

人物魔法上下文只含公开规则、本人已知完整单纹、实际引导资格与现场自有储能器物的相对充能档位。作者层耦合分类、精确容量和魔法物理参数不进入人物上下文。普通木料、职业名或愿望不能生成施法资格或能源。

当前执行器支持两项有限能源能力：`magic_energy_cost` 改善已知单纹的供能消耗，固定输出保持不变；`magic_transfer_efficiency` 改善两个相容器物间的有损转移。它们不是任意伤害、治疗或新法术核心效果的执行器。应用必须绑定本人提案中明确选择的魔纹与器物，并通过逐项发明评审；旧单项能力入口不能登记魔法契约。纯魔法不能由普通劳动或营养能力冒充，魔工结合的获批应用须至少包含一项真实魔法资源计划。

能源结算须对应实际完成的指定活动，复验器物归属、可达性、相容性、有限容量与输出，以及确认的知识和引导来源。工具须先真实制造，使用时仍须可用；声明耗材的知识型应用须实际消耗并绑定本次凭证，凭证不能跨活动复用。同一活动结算幂等，不重复扣能。世界配置不自动赠送魔纹、器物或传承；初始资源须有明确确认来源。

`GET /api/worlds/{id}/science/magic` 只读返回公开规则与已登记资源数量。前端展示魔法科研基础并按领域筛选技术卡片；空分支明确表示尚无研发成果。研究领域和离线验证样例都不计作NPC研发，旧存档也不因界面更新而生成魔法科技。

## 原理研发周期

新准备的原理科研会话采用`research_cycle_version=1`。独立原理评审通过先登记研究项目，实际完成研究周期之后才登记科技、本人知识、衍生发明与采用记录。周期仅累计绑定该项目、由实际提案人完成的研究活动，不把空等、模型响应耗时、休息或其他劳动记为研究时间。

版本1默认基础原理48个有效世界小时、工艺24小时；仅改进已有技术的工艺12小时。魔工结合乘以1.5。每段最多60世界分钟，每人每天最多预约240分钟研究。周期规则在立项时保存，所需分钟和规则版本不可更改；科技名称、方法与依赖仍由人物提案及独立评审产生，时长规则不是预置科技清单。

研究沿用现有`research`生活活动，实际扣精力并受正常饥饿、身体、位置、活动占用和行程约束。研究与日常生活共用普通居民／巡夜居民的睡眠安排，研究段不得跨过睡眠、作息或约定边界。中断段不记工时，已完成的旧研究段保留；再次结算同一段不增加进度。完成项目时还须从实际已结算工时账复核，不仅依据进度汇总值。

研究等待期间不重复请求模型。预算停止新增请求后，已提交项目仍可按正常时钟结算；`--settle-only`在原指纹、锁和无密钥配置校验后先结算研究、再结算应用，不恢复模型后端。观察时间有限，身体／资料／资格或其他阻碍导致未完成时保留项目与进度，不修改门槛。

科技卡片不展示负责人。`GET /api/worlds/{id}/science/projects`只读返回未完成项目的原理、领域、状态、工时、进度和阻碍；未完成项目单独显示，不计作已研发节点或解锁能力。达成卡片可查看真实记录的周期。旧会话沿用历史契约，旧科技未记录的周期明确显示为历史未知，不追补时长或改写已有成果。
