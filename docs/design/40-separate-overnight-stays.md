# 分房长时住宿与休息后会合

阶段40已实现两间独立房间的长时休息，以及之后回原站点室外会合的约定。真实模型、浏览器和625项相关回归已分组验收，正式本地服务已备份并更新。

## 独立邀请和固定房间分配

人物档案的“分房住宿与休息后会合”可选择双方已经实际到站的原旅行、同一站点的两间真实房间、各自入住窗、四至十二个世界小时的完整休息时长，以及休息后的会合窗。两间房不能相同，也不能使其中一人的房间成为另一人的内外层通路；允许各自经过合法的公共前厅。

`SeparateStayIntent` 使用独立的 `separate_stay_choice`／`separate_stay_intent`，支持 `propose`、`accept`、`decline`、`cancel` 和 `check_in`。提出时需要真实 `journey_id`、`own_room_id`、`other_room_id` 和带时区的 `arrival_world_time`；入住窗与会合窗各为十五至一百二十分钟，默认六十分钟，休息时长为二百四十至七百二十分钟，默认四百八十分钟。

`own_room_id` 永远分给提议者，`other_room_id` 分给收到邀请者；接受不交换房间，也不能改写时间或时长。只有收到尚有效邀请的一方可以接受或婉拒。玩家页面和自然输入仅提交玩家本人的明确选择，NPC 通过本人结构化输出独立回应，台词中的“愿意”不能替代已结算的接受。

提出时双方必须已实际到达同一旅行站点，原旅行仍有效。到场窗开始位于未来一个世界日内；原旅行期限必须覆盖最晚入住、完整休息和整个会合窗口。新安排和暂停原旅行在同一个保存点中完成，失败一起回滚；途中不能凭空改成已经到站。

## 房间、租住和逐门入住

双方各自的完整出入许可必须覆盖最晚入住至完整休息结束，校验包括真实租约、房间管理者、每层门路和实体钥匙。房租仍走原住房协商与确认流程。分房邀请不代订房、不付费、不买食物，也不授予进入对方房间、储物、身体接触或长期居住的许可；此选择没有 `allow_visit` 字段。

NPC 按自己的日程逐门进入分配给本人的房间，到达入住窗后自主创建本人的真实休息活动。玩家自行开门、进入自己的房间，再选择 `check_in`；该操作只开始玩家本人的休息，不能替 NPC 入住，也不等待对方恰好同时开始。原有个人活动和真实移动不会被住宿入口擅自替换。

入住窗起止均可开始，超过窗末才记为错过。每人从自己的实际开始时刻休息完整约定时长；一个人晚到不会缩短自己的休息，也不会拉长另一人已经开始的活动。每人都绑定独立的 `LifeActivityService` `rest` 活动编号，重启后按持久化事实继续核对。

## 身体需要、照护和中断

休息沿用真实时间、饥饿、精力与身体规则，开始前先处理用饭、伤势和已承担的紧急照护。住宿不自动进食，身体或照护需要变化仍可能中断；房间或外层许可撤销、离屋、受伤、位置变化及绑定活动提前结束也会重新核验。

维护在活动结算前检查风险，避免先给整段恢复再补记中断。worker 和主动等候按入住、活动终点、身体检查及会合等边界分段，不能一次跨过整夜直接宣告成功。NPC 赴屋的每层入口分步排程；已经到期但暂时先用饭的安排会短时复查，避免沿原一小时日程错过窗口。

一人错过或中断不会无条件停止另一人仍合法的个人休息；共同会合承诺失效时保留已经发生的个人活动和消耗。明确取消整份安排只结束仍在进行的绑定活动，不结束后来另行开始的活动。已完成的个人休息不回滚，也没有额外金钱、物品或好感奖励。

## 固定会合窗与旅行恢复

会合窗从“最晚允许入住时刻加完整休息时长”开始，长度在邀请时明确。提前休息完的人可以自行离屋和回原站点等候；双方实际站在原旅行站点室外、彼此可接触且当前没有移动或占用，才形成真实会合事实。会合窗末仍可会合，过窗未会合不会抹掉已经完成的个人休息。

休息完成、真实会合和恢复旅行分别结算。NPC 在原会合窗口内等候后续决定；玩家可提出恢复原行程，仍需另一人独立同意，再由玩家选择下一程出发。也可以选择“结束本次会合等候”，保留已完成的休息和会合事实。恢复原旅行后，旧会合约定停止继续调度，不能把已经返程的人再次拉回旧站点。

待回应、已确认或个人休息正在进行，以及尚待按约会合的安排，会阻止提前恢复原旅行；会合事实成立后不会阻挡双方恢复。原旅行结束会撤销尚未确认的邀请，已经独立接受的住宿按其自身承诺继续核验。结束住宿不自动退房、传送、付款或恢复旅行。

## 持久化与 API

`journey_separate_stays` 保存双方、原旅行与真实到站及暂停来源、两间房、入住窗、最晚休息终点、会合窗与会合事实。`journey_separate_stay_participants` 分别保存每人的房间、活动、实际起止、完成或中断结果。旧约会、短休和同房住宿的规则与时长上限保持各自原值。

`POST /api/worlds/{world_id}/player/social-choices` 接收唯一的 `separate_stay_choice`，用玩家原话证据覆盖候选陈述，并通过原选择回执保持幂等。同一请求编号不能变成另一份选择；旧回执缺少新增的空字段时仍可识别，不重复结算。

`GET /api/worlds/{world_id}/separate-stays?character_id=...` 返回当前玩家与该人物的安排；`GET /api/worlds/{world_id}/separate-stays/options/{character_id}` 只提供本人已认识或眼前可见的房间。不存在、外界或当前无法认识接触的人物不能被用来枚举住宿选项。房间选项可给出本人当前出入条件，不公布对方私有租住、钥匙或门路权限的布尔结果；完整时段规则仍在正式选择时重新核验。

## 知识与表现边界

人物档案展示双方已经明确表达的分房、时间和会合条款，以及玩家自己的活动编号与实际起止。伙伴独自在房间中是否已开始、完成或中断，尚未实际会合前统一显示“尚未向你确认”；不通过顶层状态、事件或原因绕过该边界。内部数据库可审计两人的真实独立活动，不代表这些事实已经为另一人所知。

只有各自休息且在会合窗内真正会合，才对双方公开共同履约事实。对方身体、家庭照护和个人中断细节不出现在玩家档案或另一人的模型上下文。分房不生成同房共同休息或身体接触经历。

普通对话、信笺、主动联系及自然语言入口均保留结构化意图。分房后无法面对面交谈时，可以根据已知安排处理本人的入住或退出；该入口不能借机发起新邀请、隔屋对话、交易或替对方行动。修改提示前后继续使用原有8192输入预算，不扩容，也不加入 `author_hidden` 资料。

## 验收记录与范围

相关回归覆盖33个文件、625项唯一用例；本阶段新增92项，包含36项核心、35项文字、10项API、6项自主排程及5项真实上下文预算检查。大组结果见 `run/separate-stays-final-regression.log`，最后的分房、时钟、并发和运行时整合127项见 `run/separate-stays-final-integration.log`，文件计数见 `run/separate-stays-test-collection.log`。复跑不累计为新增用例。扩展检查中的三项旧提示管线断言问题已用改前提示重放确认，未计入通过数，也未扩容输入预算。

真实模型证据为 `run/separate-stays-model-proof.json`。两间相邻但各有室外入口的私人客房在独立存档中正式登记；玩家通过原住房协商与确认真实支付12枚测试货币租住东客房两日，NPC使用自己拥有的西客房。新旅行与分房安排均由真实模型独立接受。NPC二十二点自行入屋开始休息，玩家二十二点二十分实际入住本人房间，各自完成完整八小时；先醒者离屋没有中断另一人的休息。双方七点在原站点室外实际会合，再由模型独立确认恢复，原路真实返程完成。房费与口粮购买均单独留下回执，分房安排不代付费或补资源。

首轮验收发现旧会合等候会在返程后拉回NPC，已修复：双方明确恢复原旅行时结束旧等候，保留完整休息与会合事实；自主行为也检查原旅行是否已恢复。修复后从真实模型已接受、尚未入住的隔离快照重新推进休息、会合，并重新调用模型确认恢复与实际返程，来源边界保存在证据中。修复前回执另存 `run/separate-stays-model-proof-before-reunion-release.json`，没有改写旧事实来充当复验。

浏览器证据为 `run/separate-stays-ui-proof.json`，截图及文字为 `run/separate-stays-ui-reunited.png`、`run/separate-stays-ui-reunited.txt`。实际验证了两房选项、拒绝提前入住、没有对方房间进入权、玩家真实开门入屋和使用自有口粮、本人场景面板入住、十五分钟主动等候边界、先醒者自行离屋、本人完整八小时休息、实际离屋会合，以及结束剩余等候后仍保留 `completed/met`。未会合前对方独处状态始终不公开，原旅行仍为暂停。本人操作在自己的生活场景中提供直接入口，不要求NPC在场；变更后强制重读状态，旧在途响应不覆盖新操作。
