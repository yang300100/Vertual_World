# NPC 扮演消息管线

本实现参考根目录《SillyTavern 上下文组装与生成参数 Python 移植规格》的 Chat Completion 路径，并适配本项目由数据库裁定事实的 NPC 对话。两条实际模型入口（当面交谈和联系人/信笺）共用 `world_engine/roleplay_pipeline.py`。

## 组装顺序

1. `ConversationService` 按 NPC 的可见范围收集角色卡、关系、场景、知识、记忆和历史，并保留原有资料预算记录。
2. `build_npc_prompt()` 从上下文中分离本轮输入、真实历史、可选资料和角色示例。系统规则、角色身份、知识护栏、本轮输入与输出契约是必需段。
3. 先为眼前情绪、身体不适、待办和已成立的约定留位，再从最新到最旧按完整问答组加入历史；较旧轮次一旦超预算即停止。相关知识、旧原话、亲历事件和记忆按来源预算加入；过大的单条资料或问答组可跳过。角色示例单独标成语气参考，绝不伪装成历史 NPC 原话。
4. 每次候选加入后重新计算最终 `messages` 的输入预算。必需段超限时抛出 `NpcPromptOverflow`，不会默默删除人物与事实边界。`NpcPrompt.trace` 记录段来源、估算 token 与保留状态。
5. `SamplingIntent` 与 `build_deepseek_roleplay_payload()` 分离通用采样意图和 DeepSeek 请求字段。当前 NPC 路径支持配置 `NPC_TEMPERATURE`、`NPC_TOP_P`；适配器按 DeepSeek 范围裁剪数值，对 reasoner 模型不发送这些采样字段，也不发送 DeepSeek 未支持的 `top_k` 等字段。输出上限仍为配置值与 1200 中较小者。

`scripts/inspect_npc_prompt.py` 可只读导出最终消息与 `prompt_trace`，不会调用模型或推进世界。

## 旧资料的相关性与去重

`world_engine/dialogue_relevance.py` 以正文词组匹配本轮话题，排除双方称呼和寒暄等泛问词；“继续”“然后呢”等纯续接输入可继承最近一轮的话题。这是本地字面检索，不能保证识别任意同义表达。前置资料预算复用相关性、资料精简和来源上限，避免先被无关或过大的资料挤掉相关事实，再在最终阶段删除这些资料。前置预算保留去重所需的事件身份，最终请求才移除审计字段。

普通问话允许不携带旧资料；私有记忆中重要度达到 8 的关键经历可以影响当前态度。`beliefs` 只保留相关认知、状态、置信度、核实时间及最多两条来源证据；知识块不发送文件路径、检索分数与范围元数据。会话摘要按完整问答提取相关节选，标记为 `original_excerpt`，不生成新事实；摘要哈希、原始回合索引与事件 ID 保留在服务端。旧原话只在追溯过去、询问原话或继续核对旧行动时召回，两层预算均保持问答完整。

去重只参考真正装入消息的内容。对话派生记录比较完整原话，不能因旧问题或旧台词中出现相似描述就删除后来发生的真实事件；同一事件中的额外私人反应仍可保留。相同类型和摘要的近期事件合并为一条，使用 `occurrences` 表示次数。NPC 本人的实际进行中活动通过 `npc_current_activity` 提供，不靠旧事件推断。

来源上限由最终消息计数器计算：相关知识 1200 token / 3 条，私有记忆 500 / 3 条，会话摘要 500 / 2 条，旧原话 600 / 3 组，近期亲历事件和已知事件各 350 / 3 条，认知 400 / 3 条。知识护栏保留为必需段。`prompt_trace.reason` 区分无关话题、重复内容、合并次数、未请求原话、来源预算和总预算淘汰；输入上下文及数据库原始记录不被精简过程覆盖。

## 当面表演与行动裁定

当面交谈、多人对话和玩家行动后的 NPC 回应现在把 `reply`（可说出的台词）、`stage_direction`（短暂神态与语气）和 `action_intent`（候选行动）分开。模型可以提交开关门、进出房间、转交自有物品或开始前往实际地点的意图，并在 `fallback_reply` 中准备失败时的台词。上下文会提供 NPC 实际可触及的门、自有背包物品和目的地 ID。

交付前由 `npc_performance.py` 删除命中常见门、赠物、进房及抵达断言的台词，以及会改变世界状态的表演片段。候选动作调用现有 `InteriorService.door()`、`InventoryService.transfer()` 或 `MovementService.start()`，由世界规则检查位置、权限、物品所有权、容量与忙碌状态，并记录 NPC 自己的行动事件；开始行程不会写成已经到达。交谈先通过校验，NPC 才在同一数据库事务里行动。成功后只把已裁定结果写入表演；失败时显示失败结果和备用台词。台词、表演及行动结果分别进入响应和事件元数据，历史对话只记录说出口的台词。文本过滤基于明确词形，不能证明任意自然语言陈述的真实性；世界状态只由规则服务修改。

## 兼容边界

这实现的是项目已使用的 DeepSeek 聊天补全流程，并非 SillyTavern 1.19.0 的字节级移植。项目没有 ST 的文本补全、可配置 Prompt Manager、宏语法、World Info 递归规则、swipe/continue、工具调用历史或多模态 NPC 消息入口；目前继续沿用项目的知识检索与事实权限。默认 token 计数是保守估算，不能宣称与目标模型 tokenizer 精确一致；`build_npc_prompt()` 接受可注入计数器，接入目标模型 tokenizer 后才能验证紧贴窗口边界的裁剪结果。
