# 周期作息与日常生计选择

2026-09-12。继续围绕用户可以生活其中的世界完善代码；具体居民、场所和作息内容由
内容模型填写，经作者核对后登记。不能把一张日程表当成已经发生过的生活。

## 本轮规则

- `npc_routine` 是统一注册器的新类型，只能经编年者核对。首次登记没有修订号，
  修订和停用使用当前 `expected_revision`，防止过时配置覆盖新安排。
- 每人最多十六个周期时段，支持星期、当地时刻和固定时区偏移，支持跨午夜与跨周。
  重叠时段、重复星期和不匹配的地点/配方会被拒绝。
- work、rest、craft 使用既有真实移动、持续活动、工资、材料和成果规则。
  不在抵达前开工，不立即付工资，不绕过房间权限，不占用租给别人的客房睡觉。
- 身体需求、既有活动和已确认见面优先。原时段可以暂缓、部分完成或错过，
  不自动改写约定和雇佣合同。另找工作时同时预留前往工作地与赶赴约定地点的路程。
- 默认按稳定作息安排；也可采用“维持生活储备”目标，储备足够时略过额外补工。
  日常规划器有每日劳动额度，已有工作/制作的实际耗时也会计入；不靠中止重启清空额度。
- 原工作点缺少预算或已关闭时，可在明确半径内选择可行替代场所。同一时段当天优先沿用
  已选地点，条件失效时才重选；保留选择理由及来源事件，不转移产权或创造岗位工资资金。
- 完成、部分完成、错过、主动略过、旧计划被替换分别记录。修改计划不取消已经开始的
  活动，旧活动仍按其冻结规则结算；旧计划的执行记录不会删除或当成新计划的完成量。
- 跳过的时段没有活动证据就记为未执行，不补发工资和产物。单次最多逐项记录最近七日，
  更长空白区间只记摘要；再次读取和重启不重复生成这些记录。
- 玩家仅能读取认识的居民明确公开的时段；私人休息、储备目标和替代工作判断不公开。
  NPC 自己的对话上下文可读取目标、最近执行结果及工作选择，回复仍由模型生成。

## 使用与数据

编年者页面新增周期作息 JSON 登记和读取现有配置入口，确认前能核对完整字段。
玩家场景中新增“居民公开的作息”，仅展示公开声明，不保证对方此刻已经到场。

```text
GET  /api/worlds/{world_id}/npc-routines
POST /api/worlds/{world_id}/npc-routines
     {"idempotency_key":"唯一请求键","routine":{...npc_routine配置...}}
```

提交只产生 proposed 登记，仍使用原确认接口生效。公开读取复用 `/player/experience` 的
`public_routines` 字段。`scripts/prepare_life_content.py` 新增第五种 Schema，导出配方真实 ID
和作息修订号，并校验内容模型返回的日程引用。

新表：`npc_routine_plans`、`npc_routine_occurrences`、`npc_routine_activities`、
`npc_work_preferences`、`npc_routine_cursors`。没有给正式存档自动添加作息。

## 当前边界

这是周期规划与生计偏好，尚非完整人生目标树、职业晋升、迁居或家庭计划系统。
日常规划器的劳动额度不替代所有行动权限；独立模型选择仍由既有动作规则裁决。
通勤按已有路线预计与地理距离判断，不能保证预测所有天气和路障。
位置归属无法区分的重叠地点会暂缓，不能在错误场所发工资。
