# 世界现象与中层规则框架

哥哥，世界规律由可信执行器决定；研究者只选择操作、观察和解释。框架不接收研究者的预期结论、科技名称或成功愿望来决定结果，也不需要追踪每个原子。实现采用现有材料状态、真实资源结算和有限魔法能源规则。

## 四层分工

1. **属性与机制**：物品状态和环境参数输入纯执行器，输出新的状态及有限可观察响应。
2. **实际执行**：既有工单检查人物、实物、资格、工具、能源与耗时，绑定开始时的规则版本及来源，真正结算产物和资源。
3. **现象留档**：完成来源验证后保存内部审计和公开现象，二者分开。预检及纯计算不是事实来源。
4. **人物观察**：只向实际参与并取得反馈的人物登记观察；精确仪器读数、定性器物反馈和普通可见变化使用不同通道。人物可据此提出假设，知识认证仍由上层科研流程负责。

## 首批机制

| 机制 | 已实现范围 | 对人物的反馈 |
|---|---|---|
| 材料处理 | 加热、冷却、洗涤、干燥、混合、筛分、过滤、吸附、结合处理、静置沉降、储存、成形、压实 | 工序实际结束、主副产物分离、成形外观变化；不直读内部强度或孔隙 |
| 材料量测 | 承重、渗漏、孔隙、色料固着、形变、可提取组分、颗粒、含水、发芽活力、酸碱度 | 与量器精度、检测限相符的读数；低于检测限为无法检出，不能当成零值 |
| 魔法能源 | 已知完整单纹供能、相容器物有损转移 | 供能及接收器物的储能档位；不透露耦合分类、精确容量或作者参数 |

这些是游戏近似，覆盖范围有限。机制清单不是已发现科技，也不自动给予器具、原料、魔纹、传承或施法资格。任意治疗、伤害、未知魔纹组合以及其他尚未定义的自然作用不产生猜测结果。

## 可信执行器接口

`phenomena_rules.RuleSpec`声明机制键、领域、版本、操作、指标、属性和说明。`RuleRegistry.register(spec, evaluator)`只在可信启动代码中接受执行器，同一键和版本不得替换；不同版本可以同时保留。启动后调用`freeze()`，不开放模型编写公式、SQL、Python或热替换规则的入口。

`evaluate(key, operation, version=..., **context)`指定机制与可选固定版本。执行器返回`RuleOutcome`，包括状态、版本、实际计算输出、有限反馈和作者审计输入。未知机制／操作／版本返回`unsupported`，没有输出或观察，不等同于一次实验失败。超界参数、资源不足等有效机制的执行错误沿原有失败路径处理。

执行器不自行推进时间、写库存或登记知识。组合操作仍使用`ScienceProgram`／`MethodSpec`和现有串行工单：上一步真实产物生成后，下一步才取得可操作的实物。加热接冷却、混合接过滤等组合因此保留中间状态与成本。

规则定义记录执行器源码指纹、相关物理与辅助函数指纹、材料参数或完整单纹参数。新增无关机制不替换已有执行器；改变已有机制或参数必须显式采用新版本。材料工单的`_phenomenon_version`／`_phenomenon_rule_id`以及魔法活动的`phenomenon_rule_version`／`phenomenon_rule_id`在开始时绑定。结算读取绑定版本，不能沿用默认最新版本；旧版本不存在则拒绝，不能换成新版本替旧试验生成结果。

## 现象来源与观察边界

三张新增表分别保存规则、现象和观察：`phenomenon_rules`、`phenomenon_events`、`phenomenon_observations`。记录不可修改或删除；同世界、来源类型和来源ID只能形成一条现象，单现象与单观察者只能登记一次观察。

材料现象只从已结算工单登记，检查实际参与的活动、时间及产物／量器记录；产物须等于已入物质账的真实状态。魔法现象须对应完成的活动、实际能源凭证和已更新储能。纯`computed`结果不是实测证据；预检在保存点内回滚规则登记、物资、活动、现象和观察。

刚开工就中断、或首段记录推进前受伤的活动，正常按原规则释放和结算物资，没有真实观察者时不生成现象。已有实际参与记录的中断仅返回中断说明，不冒充完成试验。

观察通道为`action`、`sight`、`instrument`、`device`。作者审计保留完整前后状态、参数和来源；人物输入只取有限反馈。旧测量记录携带的内部`sample_conditions`数值在人物输入中移除，但原记录保留供规则检验同类对照、样品量与适用条件。假说引用和证据分享继续使用真实本人证据／实际送达链路，现象观察ID已加入这条链路。

## 接口和导出

- `GET /api/worlds/{id}/science/mechanisms`：只读公开执行范围，不返回内部属性列表、参数或公式。
- `GET /api/worlds/{id}/science/phenomena?observer_id=...`：只读本世界该人物截至当前世界时间实际获得的观察；不返回作者审计。
- 科研页面提供“引擎支持的试验与现象来源”，明确实际开展仍需物资和资格，不计作科技节点。
- `audit_world`及科研导出的`现象与规则审计.json`：作者核验数据与哈希，不能投喂NPC。

旧存档未迁移时观察接口返回空列表，不初始化或补造发现；迁移也只新增空表。普通旧工单未接入新材料机制时继续原有结算，不追加新框架观察。

## 后续扩展由框架作者负责

增加新领域时，先定义有限状态和单位，再编写独立、可复现的机制，明确资源、供能、适用范围与守恒边界。随后注册版本、接入真实结算来源、定义人物能获得的感官或仪器反馈，并完成因果、权限、重复、失败和迁移验证。不能只注册一个描述就声称该领域已经能执行。

实验方案可由人物提出，规则扩展必须经过作者验证后启用，不在一次实验中临时采纳人物期望。旧在途试验保留开始时的版本；实验结束后才能决定是否升级或显式迁移。日常生活中的自动注意、选题，以及“假设—反证—知识—科技”的统一闭环属于下一层科研调度，不因本框架完成就视为已经实现。
