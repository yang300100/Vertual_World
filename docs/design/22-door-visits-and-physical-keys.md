# 22 门口拜访、短时邀请与实体钥匙

2026-09-13。延续文字生活世界的目标，让拜访有真实位置、接待者、等待和许可后果。

## 实施规则

- 站在可达入口外侧才能敲门，不能从室外越过外层房间向内层房间敲门。忙碌、移动或坐着时先结束相应动作。
- 敲门请求保存请求键、入口、访客、当时接待者、10分钟有效期和来源事件。同一请求重放不重复敲门；同一入口每人一分钟内不可重复，已有待处理拜访或邀请时不能另刷请求。
- 有效租期内接待者是当前租客，否则是房间所有者。本人必须真正位于屋内、入口可达、存活且空闲才能应门；不能让离家的 NPC 远程开门。
- 屋内等待中的接待者会因敲门结束等待。休息、工作、制作不被强行打断。访客可以在门外等待而不失去被接待的机会。
- 玩家可开门邀请、拒绝或撤回；访客可取消。应门为一次15分钟的进入许可，开门是实际状态变化。进入时消费邀请，退出后需要重新获准；权限失效不把已在屋内的人瞬移出去，仍保留安全离开路径。
- 拜访状态为 pending/invited/entered/declined/cancelled/expired，记录不被删除。读接口也实时判断过期及租客变化，不依赖一次心跳才撤销失效权限。
- 邀请仅用于进入，不赋予房屋、柜子或物品的所有权，也不扩大到永久房间使用许可。应门结果连接原敲门来源事件。

## NPC 接待

新增房间字段 `visitor_policy`：

| 配置 | 行为 |
| --- | --- |
| manual | 仅通过明确应门操作处理，NPC不自动接待 |
| authorized_only（默认） | 空闲住客开门查看，仅邀请已经具有房间使用权限者 |
| trusted_contacts | 在以上基础上，允许邀请自己已经认识、对其信任≥20且好感≥10的来访者 |

NPC先真实开门查看门口，不能隔着关门读取人物姓名或信任关系。没有获邀时恢复原先门的开闭与锁定状态，保留拒绝记录。屋内无人或忙碌只呈现等待/过期，不公开屋内人物名单、私人作息或未公开理由。
这些是作者配置的本地日常行为规则，不生成 NPC 台词。交谈仍走既有模型接口，本轮没有编写应门模板台词，也没有新增模型调用。

目前仅增加门口来访对象的局部查看，不使不同房间共享全部人物、物品或普通对话。NPC主动出门拜访、自由文本邀请的模型提案以及个性化应门对话仍待扩展。

## 实体钥匙

房间可指定 `key_item_type_id`，须引用本世界已登记、`category=tool` 且 `stack_limit=1` 的物品类型。未配置时保留原权限锁兼容行为。

配置后，门外开锁需要合法使用/进入许可，并且本人背包中实际持有匹配类型的可用钥匙。柜中、他人所有、活动预留中或已损坏的钥匙均无效。门外上锁同样核对钥匙；屋内仍可解锁离开。

钥匙通过既有真实库存、转交、储存与制作规则获得。登记房间不自动发钥匙。钥匙本身不授予合法进入或储物权限，给予许可也不会凭空产生钥匙。多个房间可以明确登记同一钥匙类型作为共用钥匙。
本轮未实现撬锁、盗窃/非法进入、配钥匙专用工序、锁芯更换与遗失钥匙撤销。

## 实现与内容

- `visits.py`：请求、接待、自动应门、时效、单次邀请与参与者视图。
- `life_door_policies`、`life_visits`：新增表；旧房间不回填钥匙或访客。
- `interiors.py`：登记、钥匙校验、邀请进入与消耗；原柜子权限独立保留。
- `interior_api.py`：`doors/{room_id}/knock`、`visits/{visit_id}/respond`、`visits/{visit_id}/withdraw`；均位于 `/api/worlds/{world_id}/player/life/` 下。
- `clock.py`：普通心跳及调速结算都处理过期和空闲 NPC 接待。
- 作者布局表单与审批显示接待规则、钥匙类型；场景页提供敲门、应门、取消和邀请状态。
- 内容 Schema 与校验器支持上述房间字段，仍先登记钥匙类型，再以真实 ID 提交房间。无正式内容自动填充。
