# 全球政体共同应对实施计划

**目标：** 构造灰孢潮，让全部 21 个有效政体的 NPC 通过报告、协商、物资与真实制作施用共同解除。

**设计：** `docs/design/18-global-cooperation-crisis.md`。在当前工作区继续已有未提交的自主危机功能，不创建缺少这些基础文件的新 checkout，不提交用户既有改动。按用户连续自主执行要求在本会话实施。

**技术：** Python、SQLite、既有规则规划与心跳，无新增依赖，无付费模型测试。

## 任务与验证

1. 先写 `tests/test_cooperation.py`：完整政体名单、送达前不知情、政策拒绝、非法签署、全流程与逐成员缺席门槛。运行，确认新领域缺失导致失败。
2. 新建 `cooperation_schema.py`、`cooperation.py` 与 `polities.py`：目录、成员权限、版本化方案、定时驿运、实物托管、结算、完成核验。增加数据库初始化、心跳与目标生成接入。
3. 新建 `npc_cooperation.py`：把协作、报告/寄送、施用等目标与算子接入统一规划器和领域执行。样本交付、craft 与成果领取复用现有算子。
4. 新建 `scripts/demo_global_cooperation.py`：全部政体首都与使节、三个批次配方及最终配方，正常心跳/规则裁决推进；保存全部证据。缺席反事实使用独立存档。
5. 每项行为先失败再通过；完成一次全量 pytest、相关静态检查和只读代码复核，修复重要缺口后复跑相关测试。生成新鲜的报告和 README 使用说明。

## 复核重点

- 名单被截断或中立地带被误当国家。
- 邮件自动把知识传播到其他成员，未来时间或已移动收件人被错误算作送达。
- 一个国家被代签、旧方案签署被新方案复用。
- 样本由库存编辑而不是合法交付进入制作，成果由库存编辑而不是活动生成。
- 缺席国家或尚未收到/施用物资仍被宣布全球解决；重复包裹重复消耗。

## 执行记录

已完成现状与正典核对，目录覆盖 20 个正式政体及阿德伦地方政权。目录、报告运输、知情授权、当前版本、异地收件、旧危机证据隔离、物品身份与容量、伪造库存和注册完整性共 13 个短检查通过。

TDD 先验证新领域不存在而失败；复核发现旧制作证据可被复用、到货合并会丢失编号，新增失败用例后修复。制作证据现在通过执行链接关联本危机的持久目标；贡献需要当前同意事件。工坊成果领取和包裹交付保留实物编号并独立核验容量。签署与施用还核验知识时间，未来送达不能提前生效。

六小时粗心跳使生活目标持续抢占协作，离线模拟改为两个世界小时，不修改生理优先级。发现寄送先于领取而反复受阻，改为领取真实成果后形成寄送动机。长模拟的公开传闻查询缺少索引，新增事件重要性时间与知情事件时间索引，保持原有传播范围。

此前维修危机的局部恢复测试依赖随机 ID 与完成顺序，完整检查暴露不稳定；测试现在明确隔离一个参与者以保留局部窗口，并保留已知联系人地址的有效性，不改变生产代码。三项相关回归通过。

两轮只读复核的重要意见均已修复，最终聚焦复核未发现重要缺口。Ruff 的 F/I 检查和相关 diff 空白检查通过。

最终正例在 1830 个世界小时（76.25 天）解除，21 个政体全部完成、四次制作、42 个包裹实际送达、21 次实际消耗施用和恢复；继续观察 24 小时后全部粮场存在真实再生。实际一国拒绝的反事实推进 1200 小时，保持 `active`，只有 20 个同意/贡献，制作、施用、恢复与粮场再生均为零。两例 HTTP 被测试阻断，模型 API 为零。可读报告、JSON 与独立数据库在 `run/cooperation-final-evidence/test_all_polities_actually_coo0/` 和 `test_a_nonparticipating_polity0/`。

完整 714 项检查运行得到 709 通过，5 项日志/图片测试因本次选择的临时目录过深触发 Windows 路径长度限制（`run/cooperation-final-pytest.xml`）；保持生产代码不变，使用短目录 `run/cv` 复跑这 5 项，全部通过（`run/cooperation-short-path-pytest.xml`）。因此全部 714 个用例均已有通过证据。另在最新测试版本运行 13 项合作短检查与 14 项旧危机回归，均通过。未重跑全球模拟，也未调用用户模型 API。
