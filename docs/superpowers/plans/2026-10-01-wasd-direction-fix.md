# WASD 方向控制修正

## 用户反馈与原因

用户发现 WASD 会生成目标点并向该点寻路。原实现确实将方向转换为约 1 公里的短程目标，复用了普通行旅；与按住方向移动、松键停止的预期不符。

## 本轮实现

- 新增 `PlayerSteeringService`，输入仅保存归一化方向，不生成 `character_movements` 或路径规划事件。
- 输入接口先通过统一世界时钟结算旧方向，再修改或停止，短按也能发生真实位移；后台心跳不会重复结算。
- 按人物、合法载具与地形速度推进，每段最多 25 米，沿方向遇到不可通行地形或地图边界停下，不绕路。
- 输入保活期限为 2 秒，另有世界时间上限；暂停世界不移动，断线、服务器重启与流速改变会停止输入，载具到期也不能继续借用。
- 保留开始、换向和停止事件，停止效果记录本次移动带来的真实坐标变化。
- 点击寻路与方向输入互斥，延迟松键不会取消点击行程；房间、活动、生命状态和载具权限继续校验。
- 前端消费方向接口返回的场景与坐标，对真实玩家位置逐帧插值；不显示方向控制的目标、路线或目标进度。
- 修正相反键同时按下、输入框获得焦点和弹窗开启时的停止行为。
- 地图页收起遮挡中央人物的固定输入栏；NPC「交谈」按钮仍切回对话界面。
- 保留原有未提交改动，未提交、推送或派生代理任务。

## 验证

- 新增“不创建目标行程”和“输入超时停止”用例，修正前均复现失败。
- 方向输入、短按、换向、松键、斜向速度、超大输入拒绝、暂停、地形、活动、载具切换、重启和点击寻路互斥测试通过。
- 移动、地形路径、时钟、生活和房间组合回归：74 项通过。
- 全量回归：659 项通过，退出码 0；仅两项已有 Starlette 依赖弃用警告。运行输出保存在 `data/wasd-regression.log`。
- Ruff F/I 与 `node --check world_engine/web/app.js` 通过。
- 使用隔离存档、120 倍世界流速，在浏览器地图页实际按 D：玩家标记横坐标由 0.5 变为 0.5044543337615577，目标标记数量为 0，路线不可见。
- 松键后再次读取，玩家标记保持同一坐标，浏览器错误日志为空；地图输入栏不可见、玩家标记可见。截图为 `data/wasd-direction.png`。
- 本地 API 与 worker 已重启，健康检查正常，真实存档的场景接口已加载独立 `steering` 状态。

## 实现边界

- 前端对服务器确认过的位置插值，实际移动仍按世界流速和真实角色速度发生。
- 地形碰撞使用现有审核通过的导航格网；方向推进采样间隔为 25 米，并未新增建筑物内部的像素碰撞。
- 持续方向输入每 450 毫秒结算一次规则心跳，未调用模型裁判。
