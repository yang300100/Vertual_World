# 运行时调试控制台设计

## 目标

通过“启动虚拟世界.cmd”启动后，保留一个可观察运行状态的 PowerShell 黑框窗口。窗口持续展示玩家行动、实际发送给模型的组装提示词、模型原始返回与解析结果、NPC 自主行动、裁定结果、错误和回退信息，便于诊断世界运行与对话行为。

## 当前行为

`scripts/start_world.ps1` 以隐藏窗口启动 API 和 worker，并将标准输出及错误分别重定向到 `logs/runtime/api.*.log` 和 `worker.*.log`。脚本完成启动后返回，因此由 `启动虚拟世界.cmd` 打开的控制台随即关闭。`AgentModelBackend.complete` 当前仅记录模型调用成功的标签、模型名、token 用量、尝试次数，或失败类型；实际请求提示词和模型响应没有进入日志。

## 设计

### 启动窗口

- API 与 worker 仍作为隐藏后台进程运行，避免把服务进程与控制台生命周期绑在一起。
- 启动器确认服务就绪并启动托盘后，在启动脚本的前台持续显示运行日志，直到用户关闭该日志窗口。
- 控制台合并显示 API 与 worker 的 stdout/stderr，并为每行加上时间及 `[API]`、`[Worker]` 来源标签。启动时展示访问地址、日志目录和快捷键提示。
- 关闭调试控制台只结束日志查看，不停止服务；停止服务仍由既有托盘菜单或停止脚本完成。重复运行启动脚本时，应复用已有服务，并允许新窗口跟随同一组日志文件。
- 保留当前日志文件，控制台只是实时观察视图；服务启动失败仍在启动器里显示错误尾部并暂停，以便查看。

### 应用与模型日志

- 使用统一的结构化日志格式，把玩家原始输入、行动解析、提供者选择、最终 ActionProposal、规则接受/拒绝及状态结算结果记为关联事件。
- 在 NPC 对话模型调用边界记录实际发送的消息（包含预算裁剪后的最终提示词），以及模型原始响应和解析后的结构化结果。记录阶段、世界、参与角色、模型、重试次数、耗时和错误/回退信息。
- 在 NPC 日常生活和自主裁判结算处记录行动意图及其结果，包含移动开始/抵达、活动开始/结束、资源采集和遇到阻碍等既有客观事件。
- API/worker 日志处理器将这些应用日志写到各自当前重定向的标准输出，使实时控制台和日志文件都能看到；默认日志级别保持 INFO，完整提示词/原始响应使用显式 DEBUG 级别，避免正常运行输出被高频内容淹没。

### 隐私边界

- 调试输出限定在用户本机控制台和项目现有运行日志，不增加远程日志上报。
- 不记录 Authorization、API key、环境变量或完整 HTTP 请求头；请求日志仅序列化模型 messages 及必要的非敏感采样元数据。
- 对日志中的凭据样式内容做防御性遮蔽。角色卡、记忆和对话本身可能含个人或私密信息，因此控制台启动时明确标注“本地调试输出可能包含角色私密内容”。

## 涉及模块

- `scripts/start_world.ps1`：服务启动后切换为前台日志观察器，合并读取四个 API/worker 输出文件。
- `world_engine/agent_llm.py`：在模型调用边界记录最终消息、原始返回和解析结果，并保留既有错误与用量日志。
- `world_engine/engine_player_intent.py`、`world_engine/player_action_flow.py`、`world_engine/npc_performance.py` 或相邻现有结算边界：补齐玩家行动与 NPC 回应/行动的关联日志，优先复用现有事件内容，避免重复构造状态事实。
- `world_engine/daily_life.py` 和 `world_engine/engine_adjudication.py`：让 NPC 自主行动和裁判结果可从 worker 控制台读取。
- `tests/test_launchers.py` 与相应 Python 单元测试：验证控制台跟随器的启动契约、模型日志内容和凭据遮蔽。

## 验收标准

1. 运行“启动虚拟世界.cmd”后，浏览器与托盘照常启动，同时前台黑框持续可见并实时显示 API/worker 日志。
2. 玩家输入一条行动后，窗口能显示输入、解析/行动提案及最终接受或拒绝结果。
3. NPC 对话模型调用能显示实际发送的裁剪后提示词、模型原始返回和解析结果，并能看出模型失败或规则回退。
4. NPC 自主行动、移动与生活活动能显示行动意图及可观察结果。
5. 关闭调试窗口不会停止 API 或 worker；使用原托盘停止命令仍能干净停止两者。
6. API key、Authorization 值和环境变量不会出现在控制台或日志文件中。

## 未包含

- 不新增网页日志查看器或远程日志服务。
- 不改变世界行动、模型提示词或 NPC 决策行为，只增加诊断可见性。
- 不要求玩家动作的每个内部函数都写单独日志；以输入、模型边界和权威结算结果为观察节点。
