# NPC 自主科研与生长科技树设计

日期：2026-10-05。状态：哥哥已确认本设计；进入实施计划阶段，产品实现与真实科研运行尚未开始。尚未调用科研 API。

## 目标与已确认约束

世界中的 NPC 依据本人的身份、目标、已有知识与实际证据，自行选问题、提出假说、安排实验、修订方法、交流成果。经过验证的可执行新能力登记为科技；后续研究可以实际复用它，逐步产生原先没有预设的依赖图。每次突破把研究过程写入世界编年。

- 哥哥允许调用现有模型 API，首轮明确选择最多12次、累计200000 token。
- API 用量包括输入、输出与提供方计入的推理用量；失败、拒绝、截断同样计账，未知用量以事先预留计入保护额度。达到上限停止新增调用，不能据此宣称达成。
- 不调用生图。不覆盖 .env，不重启旧灾难，不修改浮空城验收存档，不整体提交现有脏工作树。
- 通用能力和自然响应规则在运行前完成并冻结；运行后助手只读观察和导出。不追加实验、改库存、选研究者、修人物计划、放宽判据或提高额度帮助成功。
- 原世界观的初始人物列表为空，正式存档已有32位 NPC。测试以正式存档一致性副本为人物基线，保留身份、技能、目标、关系和既有记忆。初始工坊条件可以补齐，但不得为人物新增指定科技目标。

## 现状与缺口

已核对的代码：`autonomous_research.py`、`research_runner.py`、`collective_research.py`、`collective_types.py`、`collective_evidence.py`、`collective_work.py`、`materials.py`、`material_physics.py`、`event_log.py`、`event_history.py`、`repository.py`、`api_world.py`。

已有系统支持共振器实验、真实材料处理、预先预测、量器精度、培养时间、有限资源、通信时延和失败用量留档；现有材料指标主要服务于灰雨污染研究。共振器请求又受“正在灾害中”的候选门槛限制，无法作为日常科研调度。

缺少科技声明、真实证据认证、可复用方法登记、实际依赖追踪、突破编年、日常科研的角色调度与统一费用会话。不能把既有实验日志更名成科技树完成本目标。

正式存档未具有本工作树新增的材料研究表；副本需要正常迁移。正式存档只读核对的世界时间是2040-04-07，不能用 SQL 的内置 CURRENT_TIME 函数替代世界列，所有时间读取须限定 `w.current_time`。

## 方案选择

采用“NPC 提案 + 可执行实验 + 证据认证 + 动态依赖图”。复用已有劳动、物质账与传播机制；模型只提出行为和解释，固定执行器结算可测结果。

另两种方案分别是：只让模型讲述发明并自评成功；提前填写科技节点再让人物依次解锁。前者缺乏可复验结果，后者直接违背没有预设科技树的要求，均不采用。

## 世界规律与人物知识

依据 `docs/worldbuilding/02-magic-field-and-patterns.md`、`04-knowledge-and-magic-society.md`、`26-magic-physics-laws.md` 及 `docs/knowledge/common-character-knowledge.md`。

- 能量、物料、时间和容量真实结算；没有永动、凭空物资或自然语言改写效果。
- 作者层物理规则与人物可见知识分开。26号文档明确属于作者层，公式、精确基准与龙族/前文明答案不得进入 NPC 输入。
- 起点是传统工艺和完整单纹。人物可以提出未掌握的解释和新结构，不能将“尚未掌握”写成永远禁止研究；未验证解释仍不是既有知识。
- 基础操作是已有身体动作与工具能力，例如取样、混合、成形、加热、冷却、筛分、读取量器和调节已知完整单纹装置。它们不是待解锁科技节点，不提供命名配方、最优参数或父子路线。
- 在运行前补齐适合现有陶器匠、铁匠、织工和鉴定师的通用材料响应与量器：热处理、结构/孔隙、强度、渗漏、吸附/固着等可测性质；共振器保留供能、调谐、屏蔽与耗散响应。有限物理近似必须有明确状态量、作用条件与守恒检查，不能用模型文本判定实验成功。
- 自然规律和样品系数从基线材料、固定响应参数与记录的种子确定，不依据未来科技名称、研究者或预期路线选择。参数不作为答案发送给人物。
- 对未具备自然响应模型的提案，保存为未验证研究方向，说明实际无法执行的操作；不得凭文字宣告科技突破。不能以缺少模拟器为由禁止人物提出跨领域问题，也不能把未知效果伪装成经过验证。

## 科研会话与行动

科研是日常世界能力，不要求注入灾害。新 `science_sessions` 记录世界、启动时间、预算、源码/世界观指纹、状态和停止原因。默认不为所有世界自动花费；本次明确开启独立副本的一次科研会话。

启动前准备中立工坊条件：有限常见材料、可用手工工具、量器、正常照明/供能与物权记录。公布的是工具可用这一事实，不向人物提供研究问题、分工或路线。原有 NPC 依据职业和目标选择是否研究、继续工作、交流或等待。

在现有程序执行契约之外增加通用科研声明与方法复用接口；接口只规定必填字段与动作约束，不含任何目标科技。候选动作须包括：提出/修订可证伪假说、安排真实有对照实验、提交候选能力、复用本人已知方法、报告证据、接收方法后自行决定是否采用。

量器分辨率、耗材、供能、材料容量、工作地点、活动状态和世界时间沿正常执行路径校验。一个模型判断可以安排多步有限程序，等真实结果出现后再进行必要的新判断，不每个心跳询问所有32人。

调度依据新的实测、收到的证据、具体未决问题和执行能力；选人规则在启动前固定，运行后助手不挑选人物。语义证据指纹去重，空闲、执行中、等待培养或同一资料下反复措辞均不触发重复调用。

## 科技数据与认证

新增 `technology_candidates`、`technologies`、`technology_versions`、`technology_dependencies`、`technology_evidence`、`technology_knowledge` 与 `technology_executions`。现有实验/物质账仍是结算依据，新表通过来源标识链接，不复制成另一套无法核对的实验记录。

NPC 自己提出名称、要解决的问题、能力主张、适用条件、实验依据与可执行方法。候选与已证实科技分表或以明确状态区分；重复名称不自动成为新科技。

一项突破须同时满足：

1. 方法由 NPC 提交，能编译为既有基础动作及本人已知科技的有限调用；不能是自由文本愿望或任意 Python/SQL。
2. 能力主张可测量，阈值/比较条件在验证试验前登记，不能根据结果倒改判据。观察、理论假说与可执行工艺分别标记。
3. 支撑结果来自实际完成的实验，有可追溯样品、操作参数、计量条件、耗材与时间；不能引用未送达、未完成、别人私有或文字虚构的证据。
4. 至少两次实际执行获得可重复结果，其中至少一次使用不同真实样品；需要比较的能力有真实同类基线或对照，差异超过量器分辨率。不强制不同人物同时发现，同伴复验如发生则记录其贡献。
5. 方法带来可验证的新能力或改进；重新命名、同一证据反复登记、仅重复本来已知的基本操作不产生新节点。方法、适用条件和能力主张规范化后查重；实质修订保留版本与前后差异。
6. 依赖本人已知、已验证的父科技，并有实际调用/材料产物使用轨迹。仅在叙述中提及父科技不能生成依赖边；同世界且不能成环。

认证器只检查以上事实，不替人物选择下一次实验、修改参数、补充证明或发明名称。证据不足时原样保存候选与具体缺口，只有 NPC 可以决定下一步。

## 实际使用与继续生长

科技的过程描述登记为可复用方法，采用有类型的输入角色、参数边界、有限步骤与产物引用。调用必须显式绑定真实材料/器具，不自动复制样品或生成设备。

复用经过同一个劳动和材料执行层；用途、结果和成本留档。只有实际执行父方法或消耗其可追溯成果，才能证明子科技依赖它。后续 NPC 可以改进、合并、分支或独立发现等价方法。

科技树是由这些真实依赖产生的有向无环图；允许多父节点和独立分支。源码、测试场景、启动事件、提示词和数据库中均不提供待发现科技名单、预设边或突破顺序。

## 认知与传播

科技确实存在与某位人物知道它是两件事。本人研究、现场亲历、实际收到报告或实际学习产生 `technology_knowledge`；保留来源人物、证据、世界时间与传播层数。

转发必须真实到达后才可使用方法或证据，远方未获消息者不能读取全局科技图作为本人知识。当前已知方法优先于无关旧历史保留，沿两级对话预算进入真实角色提示词。

玩家/观察者可以查看世界科技图与历史状态；这一观察者入口不传给 NPC，也不替 NPC 同意协作。

## 每次突破写入编年

通过 `record_event` 产生重大 `world.technology_breakthrough` 事件，登记明确的地方/科研影响范围与有证据的前因，进入现有 `scope=chronicle` 查询与历史导出。

事件和可展开过程保留：谁因何问题开始研究；先前知道什么；初始假说/预测；实际试验、参数、读数和对照；失败与修订；实物和消息交接；最终验证；适用条件、限制与真实依赖。引擎用可核对模板整理原始记录，不为编年另花一次总结 API。

候选假说和失败试验也能查看，但不会被编年写成科技已经取得。编年落库与科技登记在同一事务，幂等重启不会重复宣告突破；已取得科技后被证伪时追加修订/失效事件，保留原来的历史与当时证据。

## API 费用与冻结运行

- 首轮累计调用12次、保护额度200000 token；这是世界引擎外部 API 预算，不是 Codex 会话 token 预算。
- 沿现有配置读取模型和密钥，不输出密钥。输入只含必要公开角色资料与本人证据，不发送作者层公式。
- 预留输入估算和最多8192输出 token 后才发送。完成后保存提供方实际 input/output/reasoning 用量，统一口径，避免重复计入已含输出的推理值。
- 模型网络错误不自动重试；解析/执行拒绝留存原文与诊断，不由助手补修响应。重复提交不会白花第二笔。
- 运行从一次初始工坊开放状态开始，只由普通时钟、既有生活行为和 NPC 研究计划推进；源码、设定、预算与初始库存冻结，检测外部修改会停止。
- API 失败、预算耗尽、人物选择不研究或成果不足时导出真实状态；不偷偷加码或写入“成功”。恢复后继续须沿同一存档和累计账目，不能通过另开轮次清空上限。

## 接口、界面与兼容

提供世界科研会话状态、科技列表/图、候选状态、科技过程与编年查询。玩家界面可查看节点、依赖与突破证据；科研状态明确显示待验证、已验证、失效与费用/停止原因。

科技机制接入正常心跳、NPC 输入和编年；不只是独立脚本。独立演示脚本负责准备一致性副本、开启已授权会话、冻结、观察和导出，不负责给人物写计划。

迁移可重复执行，旧存档默认没有新增科技和付费会话。正式存档与世界包文件保持原样；独立副本使用 SQLite 一致性备份，不用裸复制正在写入的主库/WAL。

## 验收与完成边界

离线验证使用测试内假后端，只检验通用契约与边界；其中的测试方法不能播种到真实运行。

必须验证：不能以文字取得科技；未完成/私有/未来证据被拒；真实材料和量器结算；预先预测不可倒填；至少两次真实重复验证；近义改名去重；真实父方法复用与防循环；科技实际可执行；消息延迟与未知人物对照；长历史不丢当前知识；突破原子进入世界编年与可展开过程；重启幂等；失败用量和预算预留；冻结检测。

真实验证只接受现有 API 输出所产生的研究行动：观察到多个非预置新能力（至少3个），至少一条由实际复用形成的科技依赖边，并确认人物能以新能力继续研究或实际使用。数量只是观察者验收门槛，不进入 NPC 输入，也不指定这些能力是什么。

如果12次/20万 token 内没有出现足够成果，功能可如实报告已实现，但自主生长目标保持未达成；不能把预制树、模型故事或测试后端的结果替代真实证据。

最终交付：代码与必要回归；被冻结的独立运行存档；科技图与每个突破的过程；世界编年记录；全部 API 用量与停止原因；中文验收报告。整个目标不能仅以“有科研按钮”或“生成几个科技名称”宣告完成。
