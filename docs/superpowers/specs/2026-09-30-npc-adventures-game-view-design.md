# NPC 通用因果行动与 2D 游戏视图设计

日期：2026-09-30

## 目的与验收口径

哥哥希望 NPC 不只写下个人目标，还能从自身需求、身份、关系、掌握的情报和世界机会中自主选择目标，连续执行真实行动；每次行动都能解释其动机、成立条件、实际结果和后续影响。冒险者接悬赏、赶路、战斗、返程、领赏只是检验通用机制的例子，不能写成唯一会运行的专用链条。哥哥也希望直接在地图上观察人物活动，以 WASD 控制玩家，在整张世界地图自由移动；进入城镇范围时自动使用城镇详图，离开后回到世界图，并能和附近人物说话、交互。当前地图内的全部 NPC 都显示标记。这是玩家界面的可见范围，不改变 NPC 的情报边界。

验收必须从实际状态、世界事件和因果关系证明目标由 NPC 自主产生、行动发生过、后果被世界接受，并影响了下一步决策；只有界面文字或模型回答声称完成，不算完成。

## 仓库现状

- `NpcGoalService` 能根据预先登记的作息计划推进储蓄与制作；`npc_todos` 会作为文字目标传给裁判。规则降级决策只从目标关键词推出单次行动；没有覆盖所有行动的持续目标选择、规划、结果核验与重规划。
- `ActionService` 是人物动作的最终规则门禁；世界事件、`action_effects` 和 `event_causes` 已存在，但后果与因果连接只覆盖部分路径。现有世界时钟、导航、战斗、经济、关系、知识及生活机制应继续作为事实来源。
- 网页已有世界图、城镇详图、点击寻路和玩家标记；完整世界快照约五秒刷新一次。地图目前不绘制全部 NPC，也没有 WASD 或交互式场景同步。世界包含世界图及大量按城镇关联的详图。

## 实现次序

先交付通用目标—行动—后果循环、行动覆盖矩阵与可读因果追踪，再用数条不同领域的链条验收，其中悬赏只占一个场景。随后交付游戏视图。两者共享现有角色坐标、世界事件和目标状态；游戏视图不成为第二套世界模拟器。

## NPC 通用目标与因果行动循环

### 目标来源与个人选择

把目标定义为“希望世界达到的可验证状态”，附上人物、动机、来源、优先级、期限、风险容忍度与状态。目标可以由饥饿和缺钱等需要、性格与身份、长期愿望、关系与承诺、已知事件及传闻、可见机会引出；人物不知道的消息不能触发其目标。候选目标按价值、成本、风险、期限和当前承诺排序，保存为什么选择或放弃。模型可提出候选愿望，但必须转换成可验证的目标并通过规则校验；模型不能声明目标已经完成。

目标不限定为单一任务类型。持续目标可以等待、执行、受阻、暂停、完成、失败或取消；吃饭和休息等紧急需求可以抢占原计划，原目标保留以便恢复。目标仅由当前真实状态满足，不能因步骤文本或模型回答而完成。目标和执行游标持久化，重启后从当前世界状态恢复。

### 通用行动算子与规划

为人物可发起的行动建立类型化算子目录。每个算子说明适用目标、候选对象、预测前置条件、预期状态变化、时间与风险成本、实际执行入口以及结果核验方式。规划器在人物可知事实中实例化候选行动，用有界的目标导向搜索组合步骤；每次只提交当前一步，行动结束后读取真实结果，再继续、改路、补资源、暂停或放弃。搜索上界和候选数量有限，避免随着人物和地点数量增长而无界扩张。

第一版以类型化谓词表示目标及前置条件，使用深度不超过八步、每层保留不超过十六个候选的回归式目标搜索。先用目标价值与紧迫性排序，再扣除预计时间、资源消耗、受伤风险及已有承诺的机会成本；同分时采用稳定次序，保证可复现。搜索结果只是当前计划，不预写未来事实。每个动作完成或被拒绝后重新评估谓词和成本，世界变化会自然改变下一步。

算子不得自己伪造执行效果。移动、工作、购买、社交、采集、制作、战斗、使用物品和协议交互仍交给现有领域服务裁决；粗略前置条件只用于规划剪枝，最终以领域服务校验为准。失败的尝试同样进入结果处理：缺钱可触发挣钱，缺货可触发寻找货源，路线受阻可改路，社交拒绝可调整对象。有限次数的退避与重规划避免无限重试。没有可执行步骤时，目标明确标为受阻并说明缺失条件。

行动目录按现有 `ActionType`、生活活动、经济效果及长期协议逐项列覆盖矩阵：每种人物主动行动都必须记录动机、执行结果与可核验后果，或明确标为纯等待并记录所耗世界时间。新增行动若未提供算子与结果适配，覆盖检查应失败，不能静默退化为一句文字。规划器不得绕开领域服务的权限、距离、资源或战斗规则。

### 因果与后果账本

每次目标采纳记录触发事实或来源事件；每次行动尝试记录所属目标、所依赖的前一步、预测效果、领域服务返回的成功或拒绝结果和真实状态变化。用现有 `event_causes` 连接“获得情报或出现需求 → 选择目标 → 行动 → 后果 → 下一步”；与人物无关的静态初始状态可作为根因事实快照，不能捏造过去的事件。扩展 `action_effects` 或等价的统一效果记录，让人物主动行动均有实际后果的领域适配；关系、金钱、库存、位置、健康、知识、时间和协议变化只从已提交事务读取。因果连接必须遵守世界时间、同世界和无环约束。

人物详情展示当前目标、下一步、受阻原因、选择理由及按时间排序的行动和后果；可展开查看各步的真实事件与因果来源。地图可以追踪所选 NPC；观察本身不触发其行动。玩家动作也进入同一结果与因果账本，计划生成只应用于自治 NPC。

### 跨领域验收场景

至少验证三条由同一套算子和规划器生成的不同链条：缺钱且需要食物的人工作、获薪后购买并进食；获得重要消息且与当事人有关的人赶路、打听并据结果改变计划；冒险者发现悬赏机会后接取、赶路、战斗、返程并核验报酬。悬赏所需的发布、接取和支付是通用机会与协议动作的数据实例，不在规划器内写死专用状态机。收益只在真实资金转移后成立，战果只在战斗事件与实际生命状态吻合后成立。

## 2D 游戏视图

### 地图与渲染

保留现有地图资源和经纬度坐标系统。新增轻量场景层，使用已有图片作底图，在画布层绘制玩家与当前地图范围内全部 NPC。世界图显示世界范围人物；城镇详图只显示该图范围内人物，并提供缩放、镜头跟随和人物选择。人物多时按屏幕范围裁剪、标签避让；鼠标与触屏都可点选。

服务端依据玩家的真实位置、城镇 `area_radius_km` 与城镇关联详图决定当前场景。进入城镇范围自动切到详图，离开自动切回世界图；坐标始终是同一套世界经纬度。缺少专用详图的城镇使用按地点范围生成的局部地图视图，不把玩家留在全球图上。手动查看其他地图与自动跟随玩家的模式分开，避免镜头争夺。

### 控制与同步

WASD 控制移动；按住持续移动，松开停止，点击地图仍可用于远距离寻路。首版不提供虚拟摇杆或方向键移动。新增受限的玩家转向接口，更新现有移动路线或短目标，不接受客户端直接设置角色坐标。服务端校验输入序号、最大速度、导航可达性、当前世界时间和并发版本；暂停世界时间时角色不移动。客户端逐帧插值或预测，收到服务端结果后平滑纠正。

新增轻量场景快照，只传当前地图需要的角色坐标、行程、地图标识、世界时间和所选 NPC 的目标与下一步摘要。游戏视图打开且可见时约每秒同步一次；页面隐藏时降频。服务端仍是位置与行动事实来源，普通完整世界快照继续用于其他管理界面。NPC 坐标随世界时钟推进而变化，前端在两次同步间平滑绘制。

玩家靠近 NPC 后可选择“交谈”“查看”“交互”；这些按钮调用既有对话和动作 API，服务端再次校验距离与可执行条件。移动输入不会绕过战斗、背包、房间和交互规则。

### 时间与规模

键盘移动使用现有世界时间和人物速度；世界加速会影响世界内位移，暂停则停止。游戏视图的客户端刷新率只影响画面，不改变世界时钟。轻量场景快照避免每秒传输地图全集；当前地图范围过滤、渲染裁剪和请求降频避免大量 NPC 时卡顿。实现时用代表性世界包做负载验收。

长距离步行与 NPC 行动仍按世界时间发生；在 1 倍流速下，跨洲旅行和数小时后的任务进展也需要对应的现实时间。游戏视图保留世界倍速控制及点击远距离寻路，逐帧动画只表现已经发生或正在进行的行程，不虚构世界进度。世界图上的密集人物标记可以合并显示，放大或选择后仍可定位其中每一名 NPC。

## 验证

1. 无玩家命令时，来自需要、关系情报和可见机会的不同 NPC 目标会自行出现并推进；工作—买食物—进食、闻讯—赶路—打听—改计划、悬赏—赶路—战斗—返程—领奖三条场景由同一规划器完成。
2. 每一种人物主动行动都有动机、规则裁决、真实效果或拒绝结果及因果链接。测试遍历行动覆盖矩阵，新增行动未接入时失败。
3. 缺钱、缺货、路线受阻、对象拒绝、目标消失、受伤、过期、服务重启和重复心跳能按同一失败反馈逻辑重规划或停止，不会伪造进展或重复奖励。
4. 在世界图与城镇图边界移动时自动切换，坐标连续；地图内所有 NPC 出现且随实际行程更新。
5. WASD 持续移动、松手停止、点击寻路、交谈与交互在桌面可用；触屏可以点选人物和远距离寻路，但没有虚拟摇杆；客户端预测不能越过服务端速度或地形校验。
6. 跑相关后端测试、完整回归与浏览器交互检查，并检查地图多人场景的同步与渲染性能。

## 明确边界

第一版是可玩的 2D 地图与角色控制，不包含动画战斗场景或完整 RPG 内容库。通用目标与行动因果机制先覆盖仓库已有的人物行动，并用不同领域的链条证明其可组合性；未来新增行动需要登记新算子与真实效果适配。地图上展示全部 NPC 是玩家界面选择；NPC 自己仍依据目击、消息与个人经历制定目标。
